# ADR-0007: Builder узлы описываются моделью способностей; совместимость связей выводится из портов

**Status:** accepted
**Date:** 2026-05-28
**Tags:** architecture, builder, frontend

## Context

До этого Builder проверял соединения только структурно (нет связи-на-себя,
дубликата, цикла). Система НЕ понимала семантику узлов: что инструмент — это
способность агента, а не отдельный шаг потока; что в триггер нельзя втекать; что
выход — тупик. Из-за этого можно было собрать бессмысленную или зацикленную схему,
а шаблоны содержали связи `agent → tool`, не соответствующие исполнению (на сервере
инструменты не исполняются как шаги — они способности агента).

Нужна модель, по которой система автоматически понимает, какие узлы существуют,
что они умеют и какие связи допустимы, — и которая масштабируется при добавлении
новых типов узлов.

## Decision

**Каждый тип узла описывается портами (входы/выходы с типом связи). Совместимость
выводится из портов, а не задаётся вручную матрицей. Два типа связей:**

1. **DATA** — поток данных (trigger → agent → … → output). DAG, циклы запрещены.
2. **ATTACH** — прикрепление способности (tool → agent). Не шаг данных, в
   topo-порядок не входит.

Фиксации:

- Инструмент = способность агента: связь всегда `tool → agent` (ATTACH), не наоборот.
- Тип связи выводится функцией `linkKind(sourceKind, targetKind)`; несовместимая
  пара → связь не создаётся.
- Источник правды о портах — `src/builder/data/nodeCapabilities.js`.
- Движок — `src/builder/services/connectionRules.js` (чистые функции:
  `evaluateConnection`, `validateGraph`, `validTargetKinds`).
- Чтобы добавить тип узла — достаточно описать его порты; правила и валидация
  пересобираются автоматически.
- Консистентность реестра, групп палитры, i18n и шаблонов проверяет
  `scripts/lint-builder-graph.mjs` (pre-commit при изменении builder-данных).
- Сопровождение — скилл `skills/builder-node-architect/`.

## Consequences

- (+) Невозможно создать семантически неверную или зацикленную схему.
- (+) Pre-run валидация даёт осмысленные предупреждения (multi-trigger,
  output-empty, tool-unattached) — защита токенов.
- (+) Добавление узла — декларативное; ошибки ловит lint в pre-commit/CI.
- (−) Встроенные шаблоны пришлось привести к ATTACH-направлению (tool → agent).
- (−) Edge-функция исполнения пока трактует ATTACH не полностью — согласование
  отложено на Фазу 4 (B-3), когда появятся реальные интеграции инструментов.

## Реализация

- Фаза 1: `nodeCapabilities.js` + `connectionRules.js` + `isValidConnection` + pre-run.
- Фаза 2: палитра (сетка + поиск) + подсветка валидных целей при перетягивании.
- Фаза 3 (этот ADR): lint-скрипт + скилл `builder-node-architect`.
- Фаза 4: согласование edge-функции с ATTACH + реальные интеграции инструментов.

Подробно — `docs/agent-builder/10-node-capability-model.md`.
