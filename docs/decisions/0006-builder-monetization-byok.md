# ADR-0006: Builder monetizes as a platform; BYOK is a trust feature; no token resale

**Status:** accepted
**Date:** 2026-05-28
**Tags:** business, strategy, builder

## Context

При тестировании B-2.2 (реальный запуск через Claude API) всплыл фундаментальный
вопрос монетизации:

> Если пользователь подключает СВОЙ API-ключ (BYOK), зачем ему наш Builder —
> он же может вызывать Claude напрямую в чате / Claude Code?

Старый Beta-план (`04-beta-90day.md`) монетизировал Builder через **лимиты
токенов** (Free 10k/mo, Pro 100k/mo …). С BYOK эта модель ломается: токены
оплачивает пользователь со своего ключа — мы не можем и не должны их
перепродавать (это было бы просто наценка на Claude).

Если вся ценность продукта = «прогнать несколько промптов», технический
пользователь воспроизведёт это в Claude Code за минуты, и сервис не нужен.

## Decision

**Builder монетизируется как ПЛАТФОРМА (flat-подписка за возможности), а не за
токены/доступ к AI. BYOK — это фича доверия, а не источник дохода.**

Принятые фиксации:

1. **Не перепродаём токены.** Пользователь приносит свой ключ; мы не делаем
   наценку. Аналогия: Figma не перепродаёт вычисления — берёт за инструмент.

2. **Продаём слой НАД API:**
   - оркестрация (автоматическая передача результата по цепочке агентов);
   - переиспользование (схема — постоянный актив: построил раз → запускаешь
     многократно → делишься с командой);
   - no-code для нетехнического пользователя;
   - обучающий слой (Atlas) — ров знаний;
   - упакованный результат (размеры, скачивание, история).

3. **ICP — нетехнический.** Product / Ops / Marketing / Strategy lead, который
   НЕ кодит. Разработчик с Claude Code — **не наш клиент**, за ним не гонимся.

4. **Tier-структура (платишь за платформу):**
   - Free: 1-3 схемы, свой ключ, базовые шаблоны, демо-режим.
   - Builder Pro (~$29/mo): много/безлимит схем, командный доступ, библиотека
     шаблонов, продвинутые узлы, история версий, обучающий слой.
   - Гейтится **функциональность платформы**, не AI-токены.

5. **Связка с Atlas Pro.** Atlas = «изучи плейбук», Builder = «собери
   автоматизацию». Одна экосистема, возможен бандл.

6. **Управляемый ключ (managed key)** — опционально, ПОЗЖЕ: для тех, кто не
   хочет получать свой ключ, мы даём ключ + наценка. Вторичный путь, сейчас
   заморожен product-first пивотом (ADR-0003).

## Consequences

**Positive:**
- Модель переживает BYOK; нет риска/расходов на чужие токены.
- Доверие: прозрачно, без скрытой наценки.
- Чёткий ICP — перестаём распылять ценность на технарей.

**Negative / risks:**
- Для savvy-юзера ценность тонкая → он уйдёт в код. **Митигация:** давим в ров —
  нетехнический ICP + курированные шаблоны/обучение (Atlas) + командное
  переиспользование и управляемость, НЕ в «мощность исполнения».
- Flat-подписка без token-markup = ниже потенциальный ARPU, чем resale-модель.
  Принимаем ради доверия и простоты; managed-key как апсайд позже.

**Что это меняет в планах:**
- `04-beta-90day.md` B-2.3 (token budgets/billing) — пересматривается: не
  token-limits как продукт, а platform-tiers. Биллинг остаётся заморожен до
  разморозки distribution (ADR-0003).
- Per-run token-контроль (output tiers S/M/L) остаётся — это UX-защита расхода
  на ключе пользователя, не монетизация.
