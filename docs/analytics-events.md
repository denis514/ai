# Аналитика: какие события шлём и как их читать

> Отправка — `src/services/analytics.js`. События уходят **только после согласия**
> на плашке (Consent Mode v2): пока человек не нажал «Принять», `gtag` не
> загружен и функция `track()` молча ничего не делает.
>
> Личные данные не отправляем: только идентификаторы контента. Текст, который
> человек ввёл сам (поисковый запрос), НЕ уходит — по поиску отправляется лишь
> факт «ничего не нашлось» и длина запроса.

## События

| Событие | Когда | Параметры |
|---|---|---|
| `page_view` | смена экрана (у нас одностраничное приложение с настоящими адресами) | `page_path`, `page_title` |
| `node_open` | открыт узел карты — любым способом: карта, поиск, Cmd+K, перекрёстная ссылка, прямая ссылка извне | `node_id`, `node_category`, `locale` |
| `tutorial_open` | открыт workflow | `tutorial_id`, `locale` |
| `tutorial_done` | workflow пройден до конца | `total_done`, `locale` |
| `prompt_open` | открыт готовый промпт | `prompt_id`, `locale` |
| `bookmark_add` | добавлена закладка | `total`, `locale` |
| `search_no_results` | поиск не дал совпадений (с задержкой 1.2 с, запросы короче 3 символов не считаем) | `query_length`, `locale` |
| `build_in_builder` | нажата кнопка «Собрать в конструкторе» в узле карты — мера того, работает ли мост карта→конструктор | `node_id`, `template_id` |
| `builder_open` | открыт конструктор | `template_id` (или `(с нуля)`) |
| `builder_dry_run` | запущен пробный прогон (без токенов) | `nodes` |
| `builder_run` | запущен настоящий прогон | `nodes` |
| `builder_run_blocked` | нажали «Запуск», но нет входа или ключа — **главная точка отвала воронки** | `reason` |

## ⏸️ ПАУЗА (решение владельца, 19.08.2026)

**Аналитику не трогаем, отчёты не собираем, цифры не обсуждаем.**

Почему: сайт хоть и опубликован, но это ещё тестовая версия — на живых
пользователях её не проверяют. Данные, которые сейчас копятся, — это заходы
владельца и разработки, выводы по ним делать нельзя.

**Что это значит на практике:**
- не строим отчёты и воронки, не приносим «цифры посещаемости» как аргумент;
- не предлагаем правки продукта со ссылкой на аналитику;
- не добавляем новые события «на будущее» — вернёмся к этому одним заходом;
- код сбора остаётся как есть и продолжает работать: выключать его смысла нет,
  а включать заново потом — лишняя работа.

**Когда снимаем паузу:** при переходе на настоящий домен. **Условие наступило
2026-08-22 — подключён `105-atlas.app` (боевой `www.105-atlas.app`).**
Пауза снимается после трёх шагов (1-2 делает владелец в панели GA):
1. поменять адрес в потоке данных на новый домен;
2. закрыть двойной счёт переходов: решено оставить НАШУ отправку `page_view`
   (у неё правильные заголовки страниц) — значит в GA: Администратор → Потоки
   данных → поток → «Улучшенная статистика» → снять галочку «Изменения в
   истории браузера»;
3. отсечь тестовый период — данные до 2026-08-22 смотреть отдельно от боевых.

Отдельно: с 2026-08-22 параллельно работает Vercel Web Analytics (без cookies,
только просмотры) — на смену домена ему ничего не нужно, он привязан к проекту.

## Как это настраивалось (если понадобится повторить)

GA4 принимает любые события сразу, но **параметры событий не попадают в отчёты,
пока их не зарегистрируют** как пользовательские параметры. Это делается один раз
руками в аккаунте (доступ есть только у владельца).

Путь: **Администратор → Отображение данных → Пользовательские определения →
Создать специальный параметр.**

Создать пять штук (область — «Событие»):

| Имя параметра | Параметр события |
|---|---|
| Узел | `node_id` |
| Категория узла | `node_category` |
| Workflow | `tutorial_id` |
| Шаблон | `template_id` |
| Причина отказа | `reason` |

После этого в отчётах появятся разрезы: какие узлы открывают, какие workflow
доходят до конца, сколько людей упирается во вход при запуске агента.

⚠️ Данные начинают собираться с момента регистрации параметра — задним числом GA
их не покажет. Чем раньше это сделать, тем раньше появится история.

## Где смотреть

- **Отчёты → Взаимодействие → События** — сколько раз что произошло.
- **Исследования → Свободная форма**: строки — «Узел», значения — «События»
  с фильтром `node_open`. Это и есть «какие темы читают».
- Воронка «карта → конструктор → запуск»: `node_open` → `build_in_builder` →
  `builder_open` → `builder_dry_run` → `builder_run` / `builder_run_blocked`.
