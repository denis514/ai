# Knowledge Structure

## Источник правды
- `src/data/mindmapData.js` — структура узлов и текст
- `src/data/prompts.js` — 10 «featured» промптов в нижней панели (quick copy)
- `src/data/promptLibrary.js` — обучающая библиотека (9 категорий, 3 уровня, ~42 шаблона)
- `src/data/tutorials.js` — обучающие модули
- `src/data/learningPaths.js` — 5 кураторских маршрутов (newcomer / engineer / researcher / automation / prompting)

## Схема узла
```js
{
  id: 'kebab-case',         // уникальный, латиница
  title: 'Короткий заголовок (≤ 30 символов)',
  icon: '🔧',               // один эмодзи
  category: 'основы',       // одна из 5
  details: {
    what:    '1-2 предложения, что это',
    why:     '1-2 предложения, зачем существует',
    when:    '1-2 предложения, когда применять',
    impact:  '1-2 предложения, что выигрываешь',
    example: '1-2 предложения, конкретный пример',
    mistakes:'1-2 предложения, типичная ошибка'
  },
  children: [ /* той же схемы */ ]
}
```

Хелпер `D(...)` в файле создаёт `details`-объект из 6 аргументов в указанном порядке.

## Ограничения
- **Глубина**: ≤ 4 уровня (root → раздел → подраздел → лист).
- **Ширина**: ≤ 12 детей у одного родителя. Больше — выделить подразделы.
- **Категории**: 5, не больше.
- **id**: уникальны, не реюзаются даже после удаления.
- **Префиксы id** (де-факто соглашение в файле): `b-` основы, `s-` skills,
  `mcp-` MCP, `cc-` Claude Code, `p-` промпты, `a-` агенты, `auto-` автоматизация,
  `proj-` Projects. Новые префиксы — фиксировать здесь.

## Жизненный цикл узла
1. **Idea** → `tasks/ideas.md` (одна строка, минимум 3 поля схемы понятны).
2. **Draft** → `content-structurer` заполняет все 6 полей.
3. **Placement** → `knowledge-architect` назначает parent и category.
4. **Insert** → `mindmap-expander` правит файл.
5. **Verify** → синтаксис JS, нет дублей id, `npm run dev` визуально ок.
6. **Deprecate** (если устарел) → метка в `tasks/backlog.md`, удаление отдельным шагом.

## Anti-patterns
- Узел без `example` или `mistakes` — не пускается в файл.
- «Обзорный» родитель без собственного `details` — запрещено, у всех узлов
  заполнены 6 полей, включая корни веток.
- Дубль на разных ветках (`Skills` в `Основы` и в `Настройка`) — недопустим,
  узел живёт в одном месте, на остальные ссылается контентом.
- Контент в `docs/` — `docs/` для правил, не для пользовательского контента.

## Prompt Library
`src/data/promptLibrary.js` — отдельный датасет, не путать с `prompts.js`.

**Категории** (`PROMPT_CATEGORIES`):
`start | writing | analysis | code | learn | creative | productivity | business | prompting`

**Уровни** (`PROMPT_LEVELS`):
`beginner | intermediate | advanced`

**Схема шаблона:**
```js
{
  id: 'kebab-id',              // уникальный в пределах библиотеки
  category: '<one of 9>',
  level: 'beginner|intermediate|advanced',
  title: 'Короткое название',
  icon: 'semantic-name',       // из Icon-реестра
  description: 'Одна строка о назначении шаблона',
  text: 'Сам текст промпта с {{placeholders_snake_case}}'
}
```

**Правила расширения:**
- Плейсхолдеры в `text` — только `{{double_braces_snake_case}}`.
- `description` — одно предложение, не дублирует `title`.
- `text` пишется по правилам `docs/prompt-guidelines.md` (роль / контекст / задача / ограничения / формат).
- Категория `prompting` — для метапромптов (CoT, few-shot, schema, self-critique).
- Уровень определяется по сложности входа, а не по теме: «архитектура» с готовой шпаргалкой может быть `intermediate`.

## Cross-links (relatedIds)

Опциональное поле `relatedIds: string[]` в схеме узла mindmap. Объявление **одностороннее**,
обратные связи вычисляются автоматически через `getRelatedNodes(id)` в `mindmapData.js`.

Правила:
- Объявлять связь только в одном из узлов пары; обратное направление подтянется само.
- Связь должна отражать **семантическое родство**, не «родитель-ребёнок» (последнее
  выражается через `children`).
- Lint (`npm run lint:data`) проверяет, что все ссылки указывают на существующие узлы.
- Поле не обязательное: большинство узлов его не имеют.

## Learning Paths

`src/data/learningPaths.js` — кураторские маршруты. Каждый — последовательность из
шагов трёх типов:
- `node`     → id из `mindmapData.js`
- `tutorial` → ключ из `tutorials.js`
- `prompt`   → id из `promptLibrary.js`

Прогресс не хранится отдельно: вычисляется из `useNodeProgress`, `useTutorialProgress`
и (косвенно) `useBookmarks`. Lint валидирует все ссылки.

Уровни маршрута: `beginner | intermediate | advanced` (как и в библиотеке).
