# Maintenance — поддержка Atlas в актуальном состоянии

Claude эволюционирует быстрее, чем большинство ПО. Без регулярного аудита Atlas
устареет за 3-6 месяцев. Этот документ описывает **процедуры поддержки** и
**политику deprecate-watch**.

---

## 1. Регулярный gap audit

**Когда:** раз в месяц (минимум) и сразу после крупных релизов Anthropic.

**Кто запускает:** Claude через skill `content-gap-auditor`.

**Что делает:**
1. Сканирует все узлы mindmap (titles + 6-вопросная схема)
2. Сравнивает с актуальным набором фич/моделей Claude
3. Возвращает список пробелов с приоритетами (critical / important / nice-to-have)
4. Предлагает конкретные узлы с parent_id и category

**Результат:** список → `tasks/backlog.md` в раздел «Контентный план».

---

## 2. Deprecate-watch

Часть контента устаревает **гарантированно**. Помечается заранее, чтобы
вовремя обновить или удалить.

### Что должно быть в deprecate-watch

- **Конкретные версии моделей** (Opus 4.7, Sonnet 4.6 и т.п.) — версии меняются.
- **Точные цифры тарифов** (цена $20, лимит 5 часов) — меняются раз в 6-12 мес.
- **Список MCP-серверов** (Linear / Figma / GitHub) — экосистема растёт быстро.
- **Доступность фич по плану** («Opus только в Pro») — Anthropic меняет границы.
- **Knowledge cutoff даты** — каждый релиз сдвигает.

### Формат пометки

В узле / шаге добавляется пометка в `pitfalls` или `details.example`:
```
[deprecate-watch: 2026-01 — проверить актуальность Opus 4.7]
```

Это не блокирует контент, но напоминает Claude (и человеку) что нужно проверить.

### Где смотреть на deprecate-watch

- `tasks/backlog.md` секция `Deprecate-watch` — список узлов, помеченных к ревизии.
- При каждом gap audit — обновляется автоматически.

## 3. Релиз-watcher (опц., P3)

**Skill `news-watcher`** (есть в backlog как P3-#12). Когда реализован:
1. Раз в неделю читает Anthropic changelog + release notes
2. Сравнивает с текущим mindmap
3. Открывает draft PR с предложениями новых узлов

Пока skill не построен — проверка ручная или через `content-gap-auditor`.

---

## 4. Жизненный цикл узла

```
       нет     →     idea    →    draft   →    in atlas    →    deprecate-watch
     (gap)        (in ideas.md)  (черновик)   (в mindmap)       (помечен к ревизии)
                                                         ↓                ↓
                                                       update          remove
                                                       (правки)        (удалить)
```

- **idea** → `tasks/ideas.md`
- **draft** → подготовка через `ai-pedagogy-architect`
- **in atlas** → `mindmapData.js`
- **deprecate-watch** → ярлык в `pitfalls`, появляется в `backlog.md`
- **update** → точечная правка через `mindmap-expander`
- **remove** → удаление с обоснованием в commit message

## 5. Checklist для нового материала

Перед слиянием нового узла / tutorial — пройти:

- [ ] Узел соответствует 6-вопросной схеме (`content-rules.md`)
- [ ] Tutorial соответствует структурным стандартам (`learning-design-rules.md`)
- [ ] Lint зелёный (`npm run lint:data`)
- [ ] Нет дублей по `id`
- [ ] Используются только семантические имена иконок (не эмодзи)
- [ ] Длина title ≤ 30 символов
- [ ] Если в `details` упоминаются версии/цифры — есть `deprecate-watch` пометка
- [ ] Если новый tutorial — есть `level / outcomes / applyIn / exercises / pitfalls`

---

## 6. Каденс

| Что | Когда |
|---|---|
| Gap audit (`content-gap-auditor`) | Раз в месяц (1-е число) |
| Прогон lint:data | Каждый commit / каждое крупное изменение |
| Обновление цен / лимитов (`pl-plans`, `pl-limits`) | Раз в квартал (или сразу после изменения Anthropic) |
| Версии моделей | Сразу после релиза нового Claude |
| MCP-серверы | Раз в квартал — что добавилось в экосистеме |
| Прогон по learning-design-rules | При каждом большом расширении контента |
