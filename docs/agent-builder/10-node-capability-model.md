# 10 — Модель способностей узлов и совместимости связей

> Статус: Фаза 1 реализована (2026-05-28). Источник правды о том, какие узлы
> существуют, что они умеют и какие связи между ними допустимы.

## Зачем

Раньше Builder проверял соединения только структурно (нет связи-на-себя, дубля,
цикла). Система НЕ понимала смысл: что инструмент — это способность агента, а не
шаг потока; что в триггер нельзя втекать; что выход — тупик. Из-за этого можно
было построить бессмысленную или зацикленную схему.

Модель «портов и типов связей» делает правила **семантическими** и
**самоописываемыми**: добавляя узел, достаточно описать его порты — матрица
совместимости и валидация пересобираются сами.

## Два типа связи

| Тип | Направление | Смысл |
|-----|-------------|-------|
| **DATA** | trigger → agent → … → output | Поток данных (бегущий текст задачи/результата). DAG, циклы запрещены. |
| **ATTACH** | tool → agent | Прикрепление способности («агент умеет искать/читать/видеть/помнить»). НЕ шаг данных, в topo-порядок не входит. |

Тип связи **выводится** из категорий пары (`linkKind(sourceKind, targetKind)`),
а не хранится отдельно.

## Порты по категориям

| Категория | Входы | Выходы |
|-----------|-------|--------|
| **trigger** | — | DATA (∞) |
| **agent** | DATA (∞) + ATTACH (∞) | DATA (∞) |
| **tool** | — | ATTACH (к агентам) |
| **output** | DATA (≥1, required) | — (тупик) |

## Матрица совместимости (выводится из портов)

| из \ в | trigger | agent | tool | output |
|--------|---------|-------|------|--------|
| trigger | ✗ | ✓ DATA | ✗ | ✓ DATA |
| agent | ✗ | ✓ DATA | ✗ | ✓ DATA |
| tool | ✗ | ✓ ATTACH | ✗ | ✗ |
| output | ✗ | ✗ | ✗ | ✗ |

**Блокируется (ошибка соединения):** tool→output, всё→trigger, agent→tool,
tool→tool, output→всё, цикл в DATA, дубликат.

**Предупреждается перед запуском (warning):** изолированные узлы, >1 триггера,
output без входящих данных, инструмент без прикрепления к агенту.

## Реализация (Фаза 1)

- `src/builder/data/nodeCapabilities.js` — `LINK`, `KIND_PORTS`, `linkKind`,
  `isEntryKind`, `isSinkKind`. Источник правды о портах.
- `src/builder/services/connectionRules.js` — `evaluateConnection` (live-проверка),
  `validateGraph` (перед запуском), `validTargetKinds` (для палитры, фаза 2).
  Чистые функции, покрыты инлайн-проверками (11/11 кейсов).
- Подключено в `BuilderApp.isValidConnection` и в pre-run валидацию (C1).
