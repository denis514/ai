> Создано: 2026-06-11. Планировочный документ ПЕРЕД сборкой. Источники: разбор
> n8n template library (10 000+ community-шаблонов как движок активации) +
> `docs/business-strategy/09-n8n-lessons.md`.

## Проблема

Сейчас 16 шаблонов, категории функциональные (`data/design/marketing/research/
logic/everyday`) и крен в IT (UX Audit, Analytics, Research). Обычный человек не
понимает, «к какой индустрии ему идти». Нужно: (1) индустриальные категории,
(2) шаблоны для НЕ-айти сфер, (3) возможность делиться своими шаблонами.

## 2. Топ-10 новых шаблонов (не-IT) — перед сборкой

Все собираются из текущих возможностей (Старт → Агент(ы) → выход), у части —
логика (Выбор/Повтор), выходы Telegram/почта/календарь. «Сложность» показывает,
что шаблон не из трёх блоков.

| # | Индустрия | Шаблон | Что получает пользователь | Логика/узлы | Выход | Сложн. |
|---|---|---|---|---|---|---|
| # | Индустрия | Шаблон | Переменные в «Старт» (≥2) | Логика/узлы | Выход | Сложн. |
|---|---|---|---|---|---|---|
| 1 | Магазин | Ответы на вопросы о заказе | `{{номер_заказа}}`, `{{вопрос_клиента}}` | Старт→Агент→**Условие** (срочно?)→Агент | Telegram/почта | beginner |
| 2 | Услуги | Напоминание о записи | `{{имя_клиента}}`, `{{дата_время}}`, `{{адрес}}` | Расписание→Агент | Telegram | beginner |
| 3 | Услуги (общепит) | Ответы на отзывы | `{{текст_отзыва}}`, `{{название_заведения}}` | Старт→**Условие-агент** (тональность сам определяет)→Агент | почта/копировать | intermediate |
| 4 | Недвижимость | Описание объекта из параметров | `{{комнаты}}`, `{{площадь}}`, `{{район}}` | Старт→Агент | текст | beginner |
| 5 | Образование | Проверка работы + обратная связь | `{{ответ_ученика}}`, `{{критерии}}` | Старт→**Условие-агент** (зачёт?)→Агент(фидбек) | почта | intermediate |
| 6 | Маркетинг | Контент-план + шлифовка идей | `{{тема}}`, `{{аудитория}}` | Старт→Агент→**Цикл** (улучшить каждую идею) | текст | intermediate |
| 7 | HR | Скрининг откликов | `{{резюме}}`, `{{требования}}` | Старт→**Условие** (соответствует?)→Агент | почта | intermediate |
| 8 | Финансы (фриланс) | Счёт + напоминание об оплате | `{{клиент}}`, `{{сумма}}`, `{{услуга}}` | Старт→Агент | почта | beginner |
| 9 | Местные услуги | Заявка с сайта, быстрый ответ | `{{имя}}`, `{{запрос}}` | **Вебхук**→Агент→**Условие** (горячий лид?) | Telegram | intermediate |
| 10 | Маркетинг/Коучи | Еженедельный дайджест по теме | `{{тема}}`, `{{количество}}` | Расписание→Агент(+поиск)→**Цикл** (по каждому источнику) | почта/Telegram | intermediate |

### Обязательные требования к КАЖДОМУ новому шаблону

1. **«Старт» с переменными — минимум 2.** В тексте «Старт» используются
   плейсхолдеры `{{ключ}}` (например `{{номер_заказа}}` и `{{вопрос_клиента}}`),
   и эти же переменные заранее заведены в блоке «Переменные» с примерными
   значениями. Цель — показать новичку механику «заполнил пропуск, один шаблон под
   разные случаи».
2. **«Старт» — задача-история** (как уже сделано): роль, ситуация, что нужно,
   результат.
3. **У каждого узла-агента — своя инструкция** (promptKey), индивидуальная.
4. **Покрытие логики по набору шаблонов** (не в каждом, но в сумме обязательно
   присутствуют все три):
   - **Условие** — простой выбор (содержит / равно / больше): #1, #7, #9.
   - **Условие-агент (автологика)** — решение принимает сам агент, без жёсткого
     правила: #3 (тональность отзыва), #5 (зачёт/незачёт).
   - **Цикл** — повтор действия N раз: #6 (улучшить каждую идею), #10 (пройтись по
     источникам).
5. **Разные выходы:** Telegram, почта, календарь — распределить по шаблонам.
6. **Ничего запрещённого:** деньги/мед-советы — только тексты и логистика.

## 3. Обмен шаблонами — как у n8n, адаптировано под Atlas

**Что у n8n:** публичная библиотека 10 000+ community-workflow — главный движок
активации. Пользователь сабмитит свою схему, другие импортируют. Фильтры по
интеграции/роли/задаче. Есть «Creator hub» + зреющий marketplace. Метаданные:
автор, использованные интеграции, описание.

**Вывод для Atlas:** полноценный маркетплейс сейчас не нужен (одиночный
основатель, product-first). Делаем фазами, переиспользуя уже готовое.

### Фаза 1 — «Поделиться кодом» (почти готово, дёшево)
У нас уже есть **двусторонняя панель «Код»** (CodePanel: схема ↔ текст). Значит
обмен можно запустить почти сразу:
- Кнопка «Поделиться» → копирует схему как компактный код/ссылку.
- Другой пользователь вставляет код → «Собрать» → схема на холсте.
- Риск-контроль: при импорте прогоняем `validateGraph` (уже есть) + НЕ переносим
  чужие ключи (только структуру и инструкции).

### Фаза 2 — Курируемая публичная галерея (модерация основателем)
- Поле `is_public` + `shared_by`/`title`/`industry` в `builder_workflows` (RLS:
  владелец правит, все читают только `is_public = true`).
- Раздел «От сообщества» в галерее шаблонов рядом с встроенными.
- Модерация вручную (флаг `approved`) — чтобы не утекал спам/секреты.
- Бейдж автора, счётчик «использовали N раз».

### Фаза 3 — Creator-слой (позже, если есть тяга)
- Профили авторов, рейтинги, «избранное», возможно платные/премиум-шаблоны.
- Только после подтверждённого спроса (Phase 0 validation, §15a).

### Безопасность обмена (важно)
- Никогда не переносить ключи/токены/`config` с секретами — только структуру,
  инструкции, демо-тексты.
- Импортированную схему помечать «из сообщества», прогонять валидатор связей.
- Публичные схемы — через модерацию, не авто-публикация.
