# План: публикация в соцсети (Threads, Instagram, YouTube)

> Создано: 2026-06-12. Планировочный документ ПЕРЕД сборкой. Статус: НЕ начато.
> Связано: `whatsapp-integration-plan.md`, `template-catalog-and-sharing.md`.
> Источники по рынку соц-API — в конце.

## Главное ограничение нашего продукта

Билдер генерирует **текст** (подписи, идеи, заголовки, описания), а НЕ видео и
картинки. Поэтому:
- Threads (текст) — агент пишет и публикует **сам**, целиком.
- Instagram/Reels — агент пишет **подпись + хэштеги**, но сам пост (фото/видео)
  должен прийти от пользователя (или, в будущем, из генерации изображений).
- YouTube — агент пишет **заголовок/описание/теги/сценарий**, но видео-файл —
  пользователя.

То есть наша сила — «умный текст под площадку», а не производство медиа.

## Реальность по платформам (июнь 2026)

| Платформа | Что можно через API | Условия | Сложность |
|---|---|---|---|
| **Threads** | Публиковать текстовые посты (+ фото/видео) через Threads Graph API | Аккаунт Meta + приложение | средне |
| **Instagram** | Фото/Reels/карусели + подпись через Instagram Graph API | Business/Creator аккаунт, привязка к FB-странице, ревью приложения (со скринкастом) | высоко |
| **YouTube** | Загрузка видео + заголовок/описание/теги (Data API v3) | OAuth Google, квота (~6 загрузок/день на дефолте) | высоко |

В отличие от WhatsApp, тут **нет правила 24ч** — публиковать первым можно. Но есть
ревью приложений, бизнес-аккаунты, квоты и правила контента.

## Что подходит билдеру (флоу)

1. **Пост в Threads (текст)** — агент пишет пост под тему и публикует. Самый
   простой и сильный кейс: всё делает ИИ.
2. **Подпись + хэштеги для Instagram** — пользователь даёт фото, агент пишет
   подпись и теги, публикуем (или отдаём на утверждение).
3. **YouTube-метаданные** — из темы/сценария агент пишет заголовок, описание,
   теги; (опц.) загрузка видео пользователя.
4. **Репост одной идеи под все площадки** — одна тема, агент готовит **разные**
   тексты: пост в Threads, подпись в IG, описание для YouTube.
5. **Контент-план → черновики** — агент готовит N постов, складывает на
   утверждение (не авто-публикация).

## Как строить (рекомендация — НЕ нативно по одной)

Делать N отдельных интеграций (Threads, IG, YouTube — каждая недели работы с
OAuth и ревью) для одиночного основателя дорого. Лучше:

- **Через единый posting-API** (Ayrshare / upload-post / Postiz / postforme):
  один коннектор оборачивает 10–15 площадок, берёт на себя авторизацию и правила
  каждой. Мы добавляем один узел-выход «Соцсети» + выбор площадки.
- Минус: зависимость от стороннего сервиса + его оплата. Плюс: вместо месяцев —
  дни, и сразу много площадок.

Альтернатива (позже, точечно): нативная интеграция самой важной площадки.

## Что нужно от пользователя

- Соответствующие аккаунты (Business/Creator для IG, канал YouTube, Meta для
  Threads) и подключение их к выбранному posting-сервису.
- Согласие на правила площадок; медиа (фото/видео) — со стороны пользователя.

## Фазы

1. **Фаза 1 — Threads (текст)**: агент пишет и публикует. Минимум зависимостей,
   максимум «магии ИИ». Можно нативно или через единый API.
2. **Фаза 2 — единый posting-API**: один узел «Соцсети» + площадки (IG-подпись,
   YouTube-метаданные, кросс-постинг текста).
3. **Фаза 3 — медиа**: загрузка фото/видео пользователя; (далеко) генерация
   изображений.

## Решение / приоритет

- **Сейчас не делаем** — это после мессенджеров и оживления Цитат/Кода.
- Когда возьмёмся — старт с **Threads (Фаза 1)**: чистый текст, всё делает агент,
  быстрый видимый результат. Дальше — единый posting-API для остального.
- Честно: авто-публикация «всё за тебя» в IG/YouTube требует медиа и ревью —
  это не «вставил токен», поэтому к ним идём через единый сервис и поэтапно.
