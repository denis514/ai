# 16 — Демо-шаблоны «Попробовать в Agent Builder» (карта узел → шаблон)

> Статус: PLAN (2026-06-11). Приоритет: **P1** (активация learn→do), но НЕ вперёд оплаты.
> Источник отбора: реальные возможности конструктора (node-defs + `atlasAnchor`),
> а не «кнопка в каждом узле». Информативные узлы демо НЕ получают (честность).

---

## 0. Зачем

Мост «учусь (узел Atlas) → пробую (рабочая схема в билдере)». В конце панели
demonstrable-узла — кнопка **«Собрать в Agent Builder»**, которая открывает
конструктор с готовым шаблоном и **предзаполненным демо-текстом в «Старте»**.

**Не делаем:** 290 шаблонов, фейковые демки под концептуальные узлы, advisory-узлы
с одинаковыми «отчётными» схемами. Расширяем по спросу (что реально кликают).

---

## 1. ОБЯЗАТЕЛЬНЫЕ правила демо-шаблона

1. **Старт всегда заполнен.** Без задачи в узле «Старт» схема не запускается. В каждом
   шаблоне «Старт» содержит **демо-текст — логическую цепочку задачи** (пример: что
   пользователю в принципе делать), как точку отправления. Текст — на **всех локалях
   (ru/en/fi)**. Пусто оставлять нельзя.
2. **Демо-тексты во всех узлах, где можно вписывать текст** (инструкции агентов,
   условия, конфиги выходов) — заполнены примерными значениями, чтобы было видно, «как
   узел мог бы работать».
3. **Сложность через логику.** Нельзя строить только из 3 блоков (старт→агент→выход) —
   слишком просто. Уровни:
   - **beginner:** линейная цепочка (старт → агент [+инструмент] → выход).
   - **intermediate:** + узел «Условие» (содержит/не содержит/равно) ИЛИ маршрутизация
     по нескольким выходам.
   - **expert:** + «Цикл» (итеративное улучшение) и/или «Условие-агент» (оркестрация
     нескольких агентов) + несколько выходов.
   Каждый demonstrable-узел по возможности получает вариант под свой уровень.
4. **Выходы учитываются:** Telegram, Email, Календарь (есть сейчас). Заложить расширение
   под MCP-серверы и иные системы (см. §4) — шаблоны проектировать так, чтобы выход легко
   заменялся на будущий коннектор.
5. **Связь узел↔шаблон** — через обратный индекс `atlasNodeId → {templateId, demoStart}`.
   Кнопка показывается ТОЛЬКО если для узла есть запись.

## 4. Каталог интеграций — рыночный анализ (2026)

> Вывод: **«топ-50 нативных интеграций сразу» — ловушка.** Каждая соцсеть требует
> отдельного OAuth, ревью приложения, медиа-правил; X-API стал платным (pay-per-use),
> TikTok/Instagram/Facebook требуют бизнес-аккаунт + видео-демо для апрува. Для
> BYOK/соло-продукта правильный путь — **агрегаторы**, а не 50 нативных коннекторов.

### Реальность по соцсетям (постинг)
- **X (Twitter):** API платный по умолчанию (pay-per-use, с фев 2026). BYOK-ключ.
- **TikTok:** Content Posting API — ревью приложения.
- **Instagram / Facebook:** Graph API, бизнес-аккаунт + видео-демо для апрува.
- **YouTube:** официальное API (чтение легко; загрузка — квоты).
- **Проще всего:** Telegram (есть ✅), Discord, Reddit, Bluesky, Threads.

### Стратегия подключения (фазами по выполнимости)
- **Фаза A (есть сейчас):** Telegram, Email (Resend BYOK), Google Calendar.
- **Фаза B (дёшево, официальные MCP/API, BYOK):** YouTube (чтение/аналитика), Notion,
  Slack, Gmail, Google Sheets/Drive, Discord, Reddit, Bluesky. Большинство — готовые
  MCP-серверы.
- **Фаза C (соцсети-постинг через ОДИН унифицированный коннектор):** вместо 5 нативных
  интеграций — один провайдер постинга (Ayrshare / Upload-Post / Post for Me / Postiz),
  покрывающий ~15 платформ (Instagram, TikTok, X, LinkedIn, Facebook, YouTube, Threads,
  Pinterest, Reddit, Bluesky, Telegram, WhatsApp, Snapchat, Google Business, Discord)
  одним BYOK-ключом. Так «много платформ» получаем без 15× работы.
- **Фаза D (длинный хвост — сотни приложений):** MCP-агрегатор (Composio = 500+
  приложений через один эндпоинт; PulseMCP-каталог 17k+). Это и есть реалистичный
  «топ-50+»: не строим по одному, а подключаем шлюз.

### Что заложить в документации/шаблонах уже сейчас
- Выход в шаблоне проектировать абстрактно («куда доставить результат») — чтобы
  Telegram/Email/Календарь легко заменялись на будущий коннектор соцсети/MCP.
- Демо-шаблоны под деятельность контент-креатора заранее предполагают выход «соцсеть»
  (пока заглушка Markdown/Telegram), чтобы при появлении Фазы C просто переключить выход.

### Источники (рынок, 2026)
- Unified social posting APIs: Ayrshare, Upload-Post, Post for Me, Postiz.
- Automation reach: Zapier 8000+, Make 1500+, n8n 1000+ интеграций.
- MCP: Composio (500+ приложений, один эндпоинт), PulseMCP (17k+ серверов), официальные
  MCP — Notion, YouTube, Slack, Gmail, Google Workspace.

## 5. План реализации (по шагам)

1. **[doc]** Эта карта (готово).
2. **Индекс `узел → {templateId, demoStart(ru/en/fi)}`** — отдельный файл данных.
3. **Кнопка «Собрать в Agent Builder»** в `DetailPanel` (рядом с «Попробовать в Claude»),
   видна только для узлов из индекса. Deep-link: открыть билдер + loadTemplate + prefill
   «Старт».
4. **Связать 13 готовых шаблонов** (быстрый результат — кнопка работает на трети списка).
5. **Заполнить демо-текст «Старта» во ВСЕХ существующих шаблонах** (ru/en/fi) — без этого
   они не запускаются у пользователя.
6. **Собрать ~10 новых шаблонов** с уровнями (beginner/intermediate/expert), используя
   логику (условие/цикл/условие-агент) и реальные выходы.
7. **Категории галереи по деятельности** + выбор роли.
8. **Фаза B интеграций** (MCP-серверы) — по мере спроса.
9. **Фаза C** (унифицированный постинг-коннектор соцсетей) — отдельное решение, BYOK.
