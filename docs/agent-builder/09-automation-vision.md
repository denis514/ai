# 09 — Automation vision: «человек в центре»

> North star Builder. Дата: 2026-05-28.

---

## Суть

В центре — **человек**. Вокруг себя он собирает агентную модель: AI делает
работу, а **результат приезжает туда, где человек работает** (мессенджер,
календарь, таск-трекер). Это «автоматизация с помощью AI», а не «чат, который
ответил».

**Пример сценария:**
> Я хочу: AI изучает страницу → делает UX-аудит → готовит файлы → ставит
> напоминание в календарь → присылает готовый материал в Telegram/Slack на
> проверку.

## Почему это и есть наш продукт (а не «обёртка над Claude»)

Голый Claude в чате не умеет: пройти многошаговый план сам, **доставить
результат** в твои инструменты, делать это повторяемо/по расписанию. Именно
«человек в центре + доставка в рабочие инструменты» — то, за что платят за
**платформу** (ADR-0006). Это конкретизация рва.

## Связь с обучающей платформой (работают в паре)

- **Atlas = «пойми концепцию»** (MCP, агент, оркестрация).
- **Builder = «сделай по-настоящему»** — практическая лаборатория.
- Каждый узел-интеграция = обучающий момент со ссылкой «Узнать больше в Atlas».

Builder — «делательная» половина обучающей платформы.

## Архитектурная модель (слои вокруг человека)

1. **Источник / «Я»** — человек, стартовая точка.
2. **Триггер** — вручную / по расписанию / входящее событие.
3. **AI-агенты** — работа (есть сейчас).
4. **Доставка / интеграции** — Telegram, Slack, календарь, файл, почта.

## Принципы реализации

- **Интеграции через MCP**, не ручные коннекторы к каждому сервису (единый
  протокол → много сервисов; ровно то, чему учит Atlas).
- **Секреты шифруются на сервере** (как API-ключ Claude), не в браузере и не
  в открытом виде в конфиге.
- **Строим по одной**, доказываем ценность петли, потом расширяем.

## Поэтапно

1. **Сейчас — одна доставка: Telegram** (низкий порог: токен бота + chat_id,
   без сложного OAuth). Доказать петлю «человек → AI → результат в мессенджер».
2. Затем — расширение через MCP (Slack, Notion, календарь).
3. Каждая интеграция — с обучающей привязкой к Atlas.

## Риски

- Поддержка многих интеграций → решается через MCP.
- Безопасность чужих токенов → шифрование + аудит перед публичным запуском.
- Соблазн «сделать всё сразу» → строго по одной.
