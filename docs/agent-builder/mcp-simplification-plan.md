# План: простое подключение MCP-серверов

> Создано: 2026-06-13. Планировочный документ. Статус: НЕ начато.
> **С чего начинаем в первую очередь: Вариант A (каталог + наш демо-сервер).**
> Связано: `social-posting-plan.md`, `whatsapp-integration-plan.md`,
> `template-catalog-and-sharing.md`.

## Проблема

Сейчас подключение MCP — голая форма «название + https-адрес + токен»
(`ApiKeysModal.jsx` → вкладка MCP, серверная `builder-mcp-manage`). Это уровень
разработчика: обычный человек не знает, где взять адрес и токен. Каталога готовых
серверов нет.

## Три варианта (по нарастанию удобства и труда)

| Вариант | Что это | Труд | Зависимости |
|---|---|---|---|
| **A. Каталог готовых серверов** | Карточки сервисов; «Подключить» сам подставляет адрес, пользователь вводит только токен + ссылка «где взять» | небольшой | нет |
| **B. Вход в один клик (OAuth)** | «Подключить Notion» → окно входа → готово, токен не нужен | большой (под каждый сервис) | OAuth-приложения |
| **C. Единый шлюз (Composio и т.п.)** | Одно подключение = сотни приложений | средний | сторонний сервис, **платный** |

Плюс «самое простое»: несколько MCP-серверов **мы хостим сами** (Supabase edge) —
у пользователя ноль настройки, жмёт «Подключить».

## Стоимость для владельца (важно)

**Вариант A ≈ $0 новых расходов.** Причина — модель BYOK (каждый со своим ключом):
- Каталог — это код (UI + данные) на текущей инфраструктуре.
- Сторонние серверы подключаются **токеном пользователя** → расход на пользователе.
- Токены Claude при запуске — из **ключа пользователя** (как сейчас).
- Наш демо-сервер — Supabase edge-функция, на старте бесплатно.

Деньги появятся только если выбрать **C (Composio)** — подписка стороннего шлюза.
B — в основном бесплатно, но у части сервисов API платный.

## Порядок (приоритет)

1. **ПЕРВЫМ — Вариант A:**
   - Демо MCP-сервер (Supabase edge `builder-mcp-demo`, 1 инструмент `get_text`)
     — он же тест MCP вживую и первый пункт каталога «подключить в один клик».
   - Каталог карточек вместо голой формы: пресет адреса + поле токена + ссылка
     «где взять токен» + краткие шаги.
2. **Потом** — добавлять реальные сервисы в каталог: по токену (A), для топ-2-3 —
   вход в один клик (B).
3. **При росте потока** — единый шлюз (C) ради массовости.

## Что трогаем при реализации

- `src/builder/components/panels/ApiKeysModal.jsx` — вкладка MCP: каталог карточек.
- Новый файл-данные каталога (`mcpCatalog.js`): {id, name, icon, url, tokenHelpUrl,
  steps}.
- `supabase/functions/builder-mcp-demo/` — минимальный MCP-сервер (демо/эталон).
- Существующее: `builder-mcp-manage` (add/list/remove), executor уже умеет MCP
  (`mcp_servers` + beta `mcp-client-2025-04-04`).

## Решение

Начинаем с **Варианта A** — он бесплатный для владельца и сразу делает подключение
«в один клик». Демо-сервер ставим первым пунктом каталога. B и C — позже и только
при спросе.
