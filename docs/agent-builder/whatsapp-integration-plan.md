# План: интеграция WhatsApp (выход + входящие)

> Создано: 2026-06-12. Планировочный документ ПЕРЕД сборкой. Статус: НЕ начато.
> WhatsApp сейчас не подключён. Выходы билдера: Telegram, Email (Resend),
> Google Календарь. Связано: `docs/agent-builder/template-catalog-and-sharing.md`.

## Зачем

Многие сервисы, магазины и мастера общаются с клиентами в WhatsApp. Это
расширяет аудиторию билдера за пределы Telegram. Но WhatsApp жёстче Telegram —
архитектуру нужно строить под его правила, иначе аккаунт банят.

## Ключевые ограничения WhatsApp (определяют, что вообще возможно)

Официально — только **WhatsApp Business Cloud API** (Meta). Два правила:

1. **Окно 24 часа.** Свободно отвечать своим текстом можно только 24 часа после
   того, как клиент написал сам.
2. **Вне окна — только одобренные шаблоны.** Чтобы написать первым (напоминание,
   подтверждение), нужен заранее утверждённый Meta **шаблон** с переменными.
   Произвольный текст «на лету» вне окна отправить нельзя.

Дополнительно: бизнес-верификация в Meta, номер телефона, **оплата за диалоги**.
Неофициальные библиотеки (whatsapp-web.js) — против ToS, бан-риск, НЕ используем.

## Что можно (флоу под правила)

| Флоу | Тип | Почему подходит |
|---|---|---|
| Ответ на входящее сообщение клиента | свободный текст | клиент написал первым → окно 24ч |
| Подтверждение заказа/оплаты | шаблон | первое сообщение → нужен шаблон |
| Напоминание о записи (по расписанию) | шаблон | первое сообщение → шаблон |
| Поддержка: сортировка входящих | свободный текст | входящее → агент отвечает/эскалирует |
| Квалификация лида из рекламы | свободный текст | человек написал → окно 24ч |

**НЕ годится:** массовые рассылки своим текстом, холодные первые сообщения
произвольного содержания — Meta блокирует.

## Что нужно построить (наша часть)

1. **Выход «WhatsApp»** (узел) — отправка через Cloud API:
   - свободный текст (если в окне 24ч),
   - либо выбор одобренного шаблона + подстановка переменных.
2. **Приём входящих** (edge-функция `builder-whatsapp-webhook`): сообщение
   клиента → запуск схемы, текст клиента становится задачей (как `builder-webhook`).
3. **Ключи**: подключение WhatsApp (токен Cloud API + phone number id) в «Мои
   ключи» — по образцу Telegram/Resend (шифрование, RLS).
4. **Окно 24ч**: трекинг последнего входящего на номер клиента, чтобы выбирать
   «свободный текст vs шаблон» и честно подсказывать в UI.
5. **Шаблоны**: минимальный список под подтверждения/напоминания + подсказка
   «текст вне окна — только из шаблона».
6. **Защита кошелька**: лимиты на диалоги (платно), как у запусков.

## Что нужно от пользователя (Meta, не код)

- Бизнес-аккаунт Meta + WhatsApp Business API + номер телефона.
- Верификация бизнеса, одобрение шаблонов сообщений.
- Это настройка на стороне Meta, не «вставил токен».

## Сложность и порядок

Сложнее Telegram (шаблоны + окно + верификация + приём входящих). Фазы:

1. **Фаза 1 — «ответ на входящее»** (обходит ограничение шаблонов): приём
   входящих + свободный ответ в окне 24ч. Самый ценный и быстрый кейс.
2. **Фаза 2 — шаблоны**: подтверждения и напоминания вне окна (выбор шаблона +
   переменные).
3. **Фаза 3 — полировка**: трекинг окна 24ч в UI, лимиты, несколько номеров.

## Решение / приоритет

Сейчас для «написать клиенту» проще и бесплатно — **Telegram** (уже работает).
WhatsApp берём, когда появятся пользователи, которым нужен именно он. Тогда
начинаем с **Фазы 1 (ответ на входящее)**.

_Файлы при реализации: новый `output-whatsapp` в `nodeTypes.js`, edge
`builder-whatsapp-webhook`, секция в `ApiKeysModal.jsx`, по образцу Telegram._
