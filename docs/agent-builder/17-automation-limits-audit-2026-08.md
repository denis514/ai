# 17. Честный аудит ограничений автоматизации (2026-08-23)

> Вопрос основателя: «где человек упрётся, когда захочет автоматизировать
> свои задачи?» Четыре независимых прогона (движок, 12 живых задач, путь по
> интерфейсу, ожидания рынка) + собственная проверка. Всё ниже — по коду,
> с точными местами. Ничего не придумано; расхождения между экспертами
> отмечены отдельно.

## 0. Чем продукт является сегодня (без прикрас)

**Конструктор цепочек из Claude-агентов с доставкой результата**, а не
автоматизатор событий. Вход — один: текст в блоке «Старт» (руками, по
расписанию или по вебхуку `POST`). Между входом и выходом — агенты с реальными
способностями (веб-поиск до 3 раз за шаг, заранее вшитый текстовый файл,
картинка, Python-код, цитаты, удалённый MCP-сервер), условия
«содержит / не содержит / равно», агент-маршрутизатор «да/нет», цикл-повтор.
Выход — четыре: текст на экране, Telegram, письмо (через свой Resend),
событие в Google Calendar.

Из 12 типичных задач малого бизнеса целиком работает **одна**: «собирай
новости по теме и присылай дайджест». Остальные упираются в три дыры ниже.

## 1. Где сошлись все четыре эксперта (ядро проблемы)

| # | Ограничение | Доказательство | Что переживает человек |
|---|---|---|---|
| 1 | **Нет входящих событий.** Единственный триггер — «Старт» (`nodeTypes.js:212-221`, singleton). Почта, сообщения в Telegram, строка в таблице, новые отзывы, RSS — ничего из этого не может запустить схему или попасть в неё. Telegram и почта — только выходы. | `builder-execute/index.ts:554-557`; `builder-webhook` требует, чтобы кто-то снаружи сделал POST | Любое расписание прогоняет **один и тот же текст из «Старта»** и выдаёт это за «новые данные». «Разбирай жалобы из почты» каждое утро разбирает одну и ту же фразу. |
| 2 | **Нет памяти между запусками.** «Память» работает только внутри одного прогона (лента шагов, `index.ts:885-889`); ни одной таблицы состояния схемы (`migrations/001…012`). | `index.ts:495-496` — состояние создаётся заново на каждый прогон | «Только новое с прошлого раза», «сообщи, если цена снизилась» — невозможно. Дайджест по утрам будет повторять вчерашнее. При этом подпись кубика обещает «долговременная память **между запусками**» (`ui.json:588`) — **ложь относительно движка**. |
| 3 | **Нет записи «куда-то».** Движок знает ровно 4 выхода (`index.ts:655, 721, 760` + текст). Google-таблицы, Notion, CRM, соцсети, HTTP-запрос наружу, ответ «в ту же ветку» — отсутствуют. | `nodeTypes.js:222-257` | «Опубликуй в Instagram», «сохрани в Notion» автосборка **молча** превращает в «покажи текст». |
| 4 | **Автосборка не умеет сказать «этого я не могу».** Валидатор проверяет только форму (`builder-generate/index.ts:63-81`), промпт не велит отказывать. На задачи 1, 3, 5, 6, 8, 10, 11 из списка модель обязана вернуть «валидную» схему из ближайших кубиков. | `builder-generate/index.ts:42-61` | Человек получает красивую, правдоподобную и **неработающую** схему и верит, что помощник «читает Google Maps». **Три из четырёх примеров, которые мы сами печатаем в строке ввода, сейчас невыполнимы** (`builder.gen.examples`). |
| 5 | **Нет шага «спроси меня».** Прогон идёт насквозь (`index.ts:534-945`); `logic-condition-agent` маскируется под подтверждение — Claude сам ответит «да» и отправит клиенту. При ошибке модели ветка «Да» выбирается молча (`:618-621`). | grep `approv|pause|waiting` пуст | Единственный разрыв с прямым репутационным риском: письмо клиенту уйдёт без проверки владельцем. |
| 6 | **Сбои автозапусков никого не уведомляют.** При дневном лимите (50 запусков / 500k токенов) **все** расписания выключаются (`index.ts:461-474`), обратного включения нет (`builder-scheduler`: `enabled: true` — 0 вхождений), а клиент обещает «до завтра» (`realExecutor.js:122`). Уведомлений о `failed` нет вовсе. | grep `notify` по `supabase/functions` пуст | Утром сводка не пришла — и человек узнает об этом, только открыв Билдер → Консоль → «Автозапуски». |

## 2. Обещания интерфейса, которые движок не выполняет (чинится текстом — дёшево)

| Обещание | Реальность |
|---|---|
| «Память: долговременная, между запусками» (`ui.json:588`) | Только внутри прогона (`index.ts:887`) |
| «Файлы: чтение PDF, CSV, Word» (`ui.json:584`) | Принимаются `.txt,.md,.json,.csv,text/*` (`BuilderApp.jsx:3426`), до 12 000 знаков, файл вшивается в схему при сборке — по расписанию всегда один и тот же |
| 8 ролей агентов | 4 из 8 (`code/designer/pm/content`) получают общий промпт-заглушку (`rolePrompts.ts:26-27`) — отличаются только иконкой |
| «Research-агент: парсинг документов, валидация источников» | Системный промпт: «reason from general knowledge» (`rolePrompts.ts:11-14`) |
| Цикл «повторить N раз» | На повторах **отключаются все инструменты** (веб, файлы, MCP, код): `index.ts:524-530`; всегда ровно N прогонов, без условия выхода |
| Примеры в строке ввода: «сводка отзывов о кафе», «напоминай клиентам письмом», «разбирай жалобы из почты» | Невыполнимы (см. §1) |
| «Автозапуски на паузе до завтра» | Выключены навсегда, пока человек не включит руками |

## 3. Тихие технические ловушки (нашёл сам / подтвердил)

- **Модель зашита: `claude-sonnet-4-5`** (`index.ts:26`), без выбора и без
  thinking/effort. По исследованию от 2026-08-22 её вывод намечен не ранее
  **2026-09-29**. Если не переключить — через ~5 недель упадут все запуски.
  Приоритет №1 по срочности.
- Telegram режет ответ до 3900 знаков молча (`index.ts:694`).
- Email с тестовым отправителем доходит **только на адрес владельца Resend**;
  об этом сообщает лишь английская ошибка после провала (`index.ts:749`).
- Условие `logic-condition` — только три строковых правила; чисел,
  «больше/меньше», регулярок нет (`index.ts:622-632`).
- «Открыть страницу по ссылке» невозможно: `web_fetch` выключен, свой
  `fetchPageText` — мёртвый код (`index.ts:80-135`).
- Стоимость веб-поиска и кода не входит в дневной лимит токенов (`index.ts:258`).
- Зависший прогон `running` не чистится; защита — только 10-минутное окно.
- Расписание всегда с размером ответа «Коротко» (`ScheduleModal.jsx:131`,
  `tier: 's'`), что бы ни выбрал человек; создать расписание можно без ключа.
- Правка схемы через 2,5 с автосохранения улетает в **живой** автозапуск;
  черновика/версии нет.

## 4. Где человек спотыкается в интерфейсе (путь до работающей доставки)

1. **Запуск тратит деньги, а потом падает на доставке** — проверка перед
   запуском не смотрит, подключён ли бот/Resend/календарь
   (`connectionRules.js:95-145`); агенты отрабатывают, токены списаны, узел
   доставки красный.
2. **15 текстов ошибок исполнения — по-английски с жаргоном** в RU/FI-интерфейсе
   (`index.ts`, `grep "await log(.*'error'"` = 15); в консоль и историю они
   попадают как есть.
3. **Ключ Claude**: ни ссылки на консоль Anthropic, ни слова про карту и
   стоимость; три названия одной сущности и пять названий одного окна.
4. **Telegram**: не объяснено про BotFather и что бот не может написать
   первым; единственная пошаговая инструкция во всём продукте — про
   @userinfobot.
5. **Расписание в UTC** с зашитой подсказкой «московское = UTC+3»; для
   Финляндии зимой неверно.
6. **Телефон**: ниже 768px — глухая стена, нельзя даже нажать «Остановить
   все», пока автозапуск тратит деньги.
7. **Гость не видит «часы»** (только при входе), хотя первый экран продаёт
   «каждое утро».
8. Словарь: «узлы», «handles», «mock-выполнение», «POST-запрос», «токены» без
   объяснения — нарушения `docs/plain-language-ui.md` на главном пути.

## 5. Расхождения между экспертами (и как разрешены)

- Продуктовый эксперт считает «событийные триггеры» тяжестью S1 («закроет
  вкладку»); UX-эксперт — блокером через другое: автосборка обещает
  результат. Это одна дыра с двух сторон — объединена в §1 п.1 + п.4.
- Движковый эксперт ставит «нет входов» рядом с «нет памяти» как равные;
  JTBD-эксперт ранжирует память выше из-за флагманского сценария «дайджест».
  Принято: память — ближе к починке (одна таблица ключ-значение на схему) и
  ломает наш же первый пример; входы — стратегически крупнее. Порядок в §6.
- Никто, кроме собственной проверки, не поднял **вывод модели из
  эксплуатации** — добавлено как срочное.

## 6. Честные приоритеты (без решений глубже одной строки)

**Сейчас, дёшево (текст и промпт, без движка):**
1. Переключить модель на актуальную (`claude-sonnet-5`) — иначе остановка.
2. Переписать подписи «Память», «Файлы», роли агентов — под факт.
3. Заменить 3 невыполнимых примера в строке ввода на выполнимые (дайджест,
   ответ на вставленный отзыв, черновик напоминания «мне»).
4. Научить автосборку отвечать «этого пока не умею» списком невозможного
   (входящая почта/Telegram, публикация, картинки, Notion/Sheets, подтверждение).
5. Проверять подключения доставки **до** траты токенов; ошибки — на языке
   интерфейса.
6. Починить обещание «до завтра»: либо включать обратно, либо писать правду,
   плюс письмо/Telegram при сбое автозапуска.

**Дальше, движок (по одному, с измерением):**
7. Память между запусками (ключ-значение на схему) — открывает «только новое».
8. Первые два входящих события: «сообщение боту» и «письмо на адрес».
9. Узел «Спросить меня в Telegram: да/нет» с продолжением прогона.
10. Один детерминированный выход-запись (HTTP/MCP-запись) и черновик/версия
    для живого автозапуска.
