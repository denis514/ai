# 13 — Автосохранение, переименование и бэкапы Builder

> Дата: 2026-05-29. Причина: пользователь потерял собранную схему при «Сохранить»
> (окно имени дёргало startBlank → очистка). Критический баг исправлен (см. ниже).
> Здесь — детальная логика автосохранения и стратегия бэкапов, чтобы работа НЕ
> терялась никогда. Главное правило: **не сломать существующий save/load**.

---

## 0. Что уже исправлено (commit f6a3499)
Окно имени получило «намерение»:
- `create` (из «Новый workflow») → `startBlank` (очистка холста — намеренно).
- `save` (из «Сохранить» / первого реального запуска) → `confirmName` сохраняет
  **текущий** холст под именем, ничего не стирая.

Это убирает саму причину потери. Дальше — страховочные слои.

---

## 1. Три уровня защиты от потери (по нарастанию)

| Уровень | Где хранится | Когда | Назначение |
|---|---|---|---|
| **L1 — черновик в браузере** | `localStorage` | при каждом изменении (debounce ~1.5с) | пережить перезагрузку/краш вкладки ДО первого сохранения |
| **L2 — автосохранение в облако** | Supabase | debounce ~3–5с, только если есть имя+id | не терять прогресс между ручными «Сохранить» |
| **L3 — версии-бэкапы** | Supabase (отдельная таблица) | при каждом сохранении (храним N последних) | откатиться к прошлой версии схемы |

L1 — самый дешёвый и закрывает 90% боли. L2 — удобство. L3 — «полноценные бэкапы».

---

## 2. L1 — черновик в localStorage (safety net)

**Ключ:** `atlas:builder:draft` → `{ ts, workflowId|null, name, nodes, edges }`.

**Запись:** debounce 1.5с на изменении nodes/edges (используем уже существующий
`isDirtyRef`/эффект). Пишем ВСЕГДА, даже без имени и id (это и есть защита
несохранённого).

**Восстановление:** при загрузке Builder, если в localStorage есть черновик
И (холст пуст ИЛИ его `ts` новее, чем `updated_at` открытого workflow) →
показать ненавязчивый баннер: «Найдена несохранённая работа — Восстановить /
Отклонить». Никогда не восстанавливаем молча (чтобы не перетереть осознанный
переход на другой workflow).

**Очистка:** после успешного сохранения в облако того же содержимого — чистим
черновик (или обновляем ts). Кнопка «Отклонить» — удаляет черновик.

**Почему безопасно:** отдельный ключ, не трогает DB-слой и load/save. Чисто
аддитивно. Если localStorage недоступен — тихо пропускаем (try/catch).

---

## 3. L2 — автосохранение в облако

Только когда workflow уже **именован и имеет id** (иначе спрашивать имя при
каждом тике — назойливо; до этого работает L1).

- Debounce 3–5с после изменения; вызывает `persist(workflowName)` (уже есть).
- Индикатор статуса «Сохранение… / Сохранено» (уже есть `saveStatus`).
- Подавление при программных мутациях — уже есть `skipDirtyRef`.
- Не автосохранять во время выполнения (execStatus==='running').

**Риск:** лишние записи в БД (delete-then-insert узлов). Митигируем debounce +
сохраняем только при реальном изменении (`isDirtyRef`).

---

## 4. L3 — версии (полноценные бэкапы)

**Таблица** `builder_workflow_versions`:
`id, workflow_id (fk), user_id, name, snapshot jsonb (nodes+edges), created_at`.
RLS — владелец (как у остальных builder-таблиц).

- На каждом сохранении пишем snapshot; храним **последние N=10** (старые чистим).
- UI: в списке workflow у каждого пункт «История» → список версий с датой →
  «Восстановить» (загружает snapshot как текущий холст, не перетирая, пока не
  нажмёшь «Сохранить»).
- Экспорт/импорт JSON одной кнопкой (`</>`) — ручной бэкап на диск.

Это отдельная миграция — НЕ трогает существующие таблицы.

---

## 5. Переименование в списке

В списке workflow (`RecentWorkflows`, `WorkflowSwitcher`) рядом с «×» (удалить) —
кнопка **edit (карандаш)**:
- клик → inline-поле или мини-модалка с текущим именем → Enter/Сохранить.
- storage: новая функция `renameWorkflow(id, name, userId)` (cloud: `update name`;
  local: правка в массиве). Не трогает nodes/edges.
- После переименования — бампаем `wfVersion`, чтобы список обновился; если это
  открытый workflow — обновляем `workflowName`.

## 6. Порядок внедрения (план)

1. ✅ **Критический фикс save-reset** (сделано, f6a3499).
2. **L1 — localStorage-черновик**: запись (safety capture) + баннер восстановления. [S]
3. **Переименование в списке** (edit-кнопка + `renameWorkflow`). [S]
4. **L2 — облачное автосохранение** (debounce, только для именованных). [S/M]
5. **L3 — версии-бэкапы** (миграция + UI истории + экспорт JSON). [M]

Каждый шаг — отдельный коммит, после каждого `npm run build` + проверка, что
ручной save/load по-прежнему работает.
