# Scaling Rules

Правила, которые держат проект здоровым при росте.

## Contentscale
- **Узлов в одной ветке:** ≤ 12. Больше — разбиваем на подразделы.
- **Глубина дерева:** ≤ 4 уровня от root.
- **Узлов всего:** до ~200 без оптимизации layout-а; дальше — пересмотр `useMindmapLayout`.
- **Размер `mindmapData.js`:** если > 150 KB — выносим в `src/data/sections/*.js`
  и реэкспортируем из `mindmapData.js`.

## Skill / prompt scale
- **Skills:** не больше ~20. Если близко к лимиту — пересмотри, нет ли дублей.
- **Prompts:** не больше ~30. Если больше — часть превращается в skill.
- **Один skill = одна зона ответственности.** Если skill «и про А, и про Б» —
  разделить.

## Docs scale
- `docs/` остаётся плоским. Один файл = одна тема. Никаких подпапок.
- Файл > 300 строк — повод разбить.

## React / build scale
- **Time-to-first-render:** ≤ 1.5 с на mid-range mobile.
- **Bundle size:** дополнительные зависимости — взвешиваем bundle, фиксируем
  в `architecture.md`.
- **Components:** один компонент = один файл. Файл > 300 строк — рефакторим.

## Task scale
- `tasks/current.md`: до 5 активных задач. Больше — переноси в backlog.
- `tasks/backlog.md`: groomed раз в N итераций, deprecated удаляются.

## Anti-bloat правила
- Никаких новых runtime-зависимостей без обоснования и записи в `architecture.md`.
- Никаких новых верхнеуровневых папок без обновления `CLAUDE.md`.
- Никаких новых категорий, если тема укладывается в 5 существующих.
- Никаких подпапок в `prompts/`, `docs/`, `tasks/`.

## Когда пересматривать архитектуру
- Mindmap превысил 200 узлов.
- `mindmapData.js` стал тяжелее 150 KB.
- Появилась повторяющаяся потребность, не покрытая существующими skills.
- Стек упёрся в ограничения (например, нужна совместная работа > 1 пользователя).

В этих случаях — RFC-документ в `docs/` с предложением и решением.
