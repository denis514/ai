# Prompt Guidelines

Единые правила написания промптов в этом проекте.
Применяются и к `src/data/prompts.js`, и к `prompts/*.md`, и к system-prompts
для агентов.

## Структура (обязательная)

```
# Роль
Ты — <конкретная роль, не "ассистент">

# Контекст
<минимум того, что модель должна знать>

# Задача
<одно действие, конкретно>

# Ограничения
- что НЕ делать
- какие границы соблюдать

# Формат вывода
<markdown | json | список | таблица — однозначно>
```

## Принципы
1. **Одна задача — один промпт.** Если промпт делает «исследуй и напиши и отрефакторь» —
   разбей.
2. **Роль конкретна.** «Senior UX-аудитор», «React Frontend Architect», а не «ассистент».
3. **Формат вывода однозначен.** Без формата модель будет угадывать.
4. **Антипаттерны важнее правил.** «Не пиши вводных» работает лучше «пиши кратко».
5. **Плейсхолдеры** — `{{snake_case_in_braces}}`. Никаких `<placeholder>`, `[x]`, `$var`.
6. **Длина.** > 30 строк — повод разбить.

## Что НЕ писать
- «Будь полезным» / «отвечай подробно» / «думай шаг за шагом» — это шум,
  современные модели делают это сами.
- «Если не знаешь — не выдумывай» — это уже встроено в Constitutional AI.
- Эмоциональные манипуляции («это очень важно»).
- Многоэтажные иерархии вложенных правил.

## Few-shot
Использовать **только** если без примеров модель ошибается.
Один-три пары input/output, по реальным случаям. Никаких синтетических.

## System prompts
- Живут в Projects (claude.ai) или в `CLAUDE.md` (Claude Code).
- Декларируют **стабильное поведение**, а не разовую задачу.
- В системном промпте — роль, стиль, ограничения. В пользовательском — задача.

## Reuse
- Если промпт может пригодиться снова → `prompts/<action>.md`.
- Если попадёт в UI mindmap → `src/data/prompts.js` (10 готовых сейчас).

## Checklist
- [ ] роль конкретна
- [ ] задача в одном предложении
- [ ] формат вывода однозначен
- [ ] есть «что НЕ делать»
- [ ] плейсхолдеры `{{snake_case}}`
- [ ] длина ≤ 30 строк (иначе разбить)
