# AI Workflows

Этот файл — операционный мануал: **что Claude делает, когда пользователь
говорит X**. Любой workflow ниже опирается на skills и prompts из проекта.

---

## WF-1. «Добавь узел про <тема>»
1. `claude-expert` — проверь, что знание про Claude корректно.
2. `knowledge-architect` — найди parent, category, проверь дубли.
3. `content-structurer` — заполни 6 полей `details`.
4. `mindmap-expander` — внеси правку в `src/data/mindmapData.js`.
5. Обнови `tasks/current.md`: что добавлено.

## WF-2. «Расширь раздел <id>»
1. Прочитай существующий раздел: title, дети, category.
2. `knowledge-architect`: сколько детей? нужен ли подраздел?
3. Сгенерируй 3-5 кандидатов через `content-structurer`.
4. Согласуй с пользователем 1-3 финалиста.
5. `mindmap-expander` — добавь.

## WF-3. «Создай AI workflow для <задача>»
1. `ai-workflow-builder` — собери YAML-сценарий.
2. Если содержит MCP — `mcp-specialist` проверит подключение.
3. Если содержит автоматизацию — `automation-architect` оформит trigger / kill switch.
4. Готовый сценарий → потенциальный узел в категории `агенты` (через WF-1).

## WF-4. «Объясни <фича Claude>»
1. `claude-expert` даёт фактическую справку.
2. Если знания нет в mindmap → предложи добавить через WF-1.
3. Ответ пользователю в формате: факт → пример → антипаттерн.

## WF-5. «Напиши/улучши промпт»
1. `prompt-engineer` — построить по шаблону Роль / Контекст / Задача / Ограничения / Формат.
2. Если промпт переиспользуемый — в `src/data/prompts.js` (через user approval).
3. Если разовый — в `prompts/<action-name>.md`.

## WF-6. «Сделай UI-правку»
1. `react-knowledge-ui` — единственный skill, имеющий право трогать `src/components/`.
2. `accessibility-review` — обязательная проверка после UI-изменений.
3. Прогон `npm run build` (или просьба к пользователю).

## WF-7. «Расскажи, что сейчас в проекте / что в работе»
1. Прочитай `tasks/current.md`, `tasks/backlog.md`, `tasks/roadmap.md`.
2. Кратко: что активно, что в очереди, что недавно сделано.
3. Не выдумывай прогресс — пиши только то, что в файлах.

---

## Универсальные правила
- **Skills — атомарны.** Не вызывай несколько skills из одного, цепочку
  оркестрирует workflow (этот файл) или сам Claude.
- **Файл = источник правды.** После любого изменения — `tasks/current.md` обновляется.
- **Не запускай разрушительные команды.** `rm -rf`, `git reset --hard` и т.п. —
  только с явного согласия пользователя.
- **При сомнении — спроси.** Если parent неоднозначен, категория не очевидна,
  схема узла неполна — задай вопрос, не выдумывай.
