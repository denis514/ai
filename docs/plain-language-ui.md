# Правило: тексты интерфейса — простым языком для обычного человека

**Статус: ОБЯЗАТЕЛЬНО.** Касается ВСЕХ текстов, которые видит пользователь:
справка Agent Builder (`builder.help.*`), подписи узлов, подсказки, пустые
состояния, тосты, онбординг, тексты шаблонов.

## Кто наш пользователь

Обычный человек, **не разработчик**. Никогда не строил автоматизации, не знает
терминов. Блогер, владелец маленького магазина, администратор, фрилансер.
Он не должен ничего «изучать» — он должен **сразу понимать, что получит**.

## Правила

1. **Ноль терминологии.** Запрещены: «узел» (→ «блок»), «нода», «логика»
   (→ «выбор/повтор»), «поток данных», «инстанс», «парсинг», «вебхук» без
   объяснения, «Markdown», «токен» без пояснения, «плейсхолдер» (→ «пропуск»),
   «оператор», «итерация», «эндпоинт». Если термин неизбежен — объясни одной
   простой фразой рядом.
2. **Объясняй результат, а не механику.** Не «узел трансформирует вход», а
   «помощник сделает из этого готовый ответ». Человеку важно «что я получу».
3. **На «ты/вы» — как в продукте** (сейчас «вы» в справке Builder — держать
   единообразно в пределах поверхности).
4. **Короткие фразы.** Одна мысль — одно предложение. Без «стены текста».
5. **Примеры из жизни.** «Погода в {{город}}», «ответить клиенту», «отзыв с
   жалобой» — а не абстрактные «entity» и «payload».
6. **Совпадение с тем, что на экране.** Если в интерфейсе кнопка называется
   «Старт» — в справке тоже «Старт» (в кавычках), чтобы человек нашёл.
7. **Продвинутое — помечать как необязательное.** «Код», «вебхук» — «это для
   продвинутых, в начале не нужно», чтобы новичок не пугался.

## Без «машинных» символов (ОБЯЗАТЕЛЬНО)

Тексты должны выглядеть так, будто их писал человек, а не сгенерировала машина.

- **Стрелки `→ ← ↔ ⇒` в прозе запрещены.** Вместо «А → Б → В» пишем словами:
  «сначала А, потом Б, потом В». Вместо пути меню «Старт → Переменные → Добавить»
  пишем «Старт, затем Переменные и Добавить».
  Исключение: ASCII-схемы внутри узлов Atlas (Systems), где стрелка — часть
  диаграммы. Там она осмысленна, не трогаем.
- **Не злоупотребляем тире `—`.** В русском тире — нормальный знак, но машинный
  почерк — это тире на каждом шагу как пауза. По возможности перестраиваем фразу
  на обычную пунктуацию (запятая, двоеточие, точка). В UI-текстах (Помощь,
  шаблоны, подсказки) стремимся к нулю «—». В контенте Atlas допустимо там, где
  это естественный русский, но без перебора.
- Проверка: `npm run lint:text` (флагует стрелки в `builder.*` и считает тире).

## Проверка перед коммитом

«Поймёт ли моя мама, которая не программист?» Если в тексте есть слово, которое
непрограммист пойдёт гуглить — заменить.

## Где это применяется в первую очередь

- `src/builder/components/panels/HelpPanel.jsx` + `builder.help.*` в
  `src/locales/{ru,en,fi}/ui.json` — вкладка «Помощь».
- Подписи и подсказки узлов (`nodeTypes.js`, `nodeGuides.js`).
- Тексты шаблонов (`builder.template.*`).
