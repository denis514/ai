# Learning Design Rules

Правила проектирования обучающих материалов **для AI** (Claude в частности).
Отличаются от классического обучения софту, потому что AI — **вероятностный**,
**многомодельный**, **быстро эволюционирующий** и **контекст-зависимый**.

Применяются ко всему: новые узлы mindmap, tutorials, library templates, paths.

---

## 10 правил AI-обучения

### 1. Probabilistic mindset, not procedural
Обучая софту, ты говоришь «нажми X, получишь Y». В AI это не работает — один и
тот же промпт даёт разные ответы.

**Делай:** «Ожидай ответ примерно такого вида / в таком формате» + конкретный пример.
**Не делай:** «Введи это — Claude ответит так-то и так-то» (точно).

### 2. Concrete → abstract
Мозг ловит конкретное быстрее теории. Сначала пример, потом обобщение.

**Делай:** «Вот два промпта (плохой vs хороший). Заметил разницу? Теперь правило».
**Не делай:** «Промпт-инжиниринг — это дисциплина...» → потом примеры.

### 3. Show failure first
AI часто учат на успешных примерах. На самом деле быстрее учишься на провалах.

**Делай:** «Вот что бывает с однострочным запросом → теперь добавь структуру».
**Не делай:** только идеальные кейсы — пользователь не научится понимать почему.

### 4. Verify, don't trust
Каждый шаг обучения = инструкция «как проверить, что вышло как надо».
Это специфика AI: модель может «уверенно» ошибаться.

**Делай:** В каждом шаге — `validate`-блок с конкретным признаком успеха.
**Не делай:** «получишь результат» без критерия проверки.

### 5. Cost is part of the lesson
Токены / время / выбор модели — это не «техническая деталь», а pedagogical content.
Если не учишь экономии — пользователь сожжёт лимиты за неделю.

**Делай:** В шагах модели/Project/Skill упоминай tradeoff (Opus дорого, Haiku хватит).
**Не делай:** «всегда Opus, не экономь» — формирует анти-привычку.

### 6. Multi-modal awareness
Современный AI работает не только с текстом: образы, файлы, web, код.
Обучение должно покрывать все каналы, а не только chat.

**Делай:** разделы про vision / files / web search / computer use должны быть в карте.
**Не делай:** ограничивать обучение только «как написать промпт».

### 7. Models evolve, content must too
Конкретные фичи (например «Opus 4.6 поддерживает X») устаревают за 3-6 месяцев.
Учи **принципам**, помечай конкретику как **deprecate-watch**.

**Делай:** «Выбирай модель по силе / скорости / цене» (принцип) +
«На момент написания: Opus, Sonnet, Haiku» (конкретика с пометкой).
**Не делай:** «Opus 4.6 умеет X» как незыблемый факт.

### 8. Limits are pedagogical content
Тарифные планы, rate limits, context-windows — это не «справочная информация»,
а часть обучения. Без них пользователь не понимает, почему Pro ему нужен / не нужен.

**Делай:** отдельный раздел про планы и лимиты, обновляется регулярно.
**Не делай:** прятать инфо о лимитах в FAQ — она нужна на этапе обучения.

### 9. Tool ecosystem layer
Claude — это не одна модель, а слой: claude.ai / Mobile / Code / API / MCP / Apps.
Обучение должно учить **выбору слоя**, не только «как написать сообщение».

**Делай:** «Тебе нужен Project (claude.ai) или CLAUDE.md (Code)?» — обучай выбору.
**Не делай:** учить одному интерфейсу как единственному.

### 10. Practice loop = exercises
Каждый концепт = упражнение для проверки собственной задачи пользователя.
Без переноса на свою задачу обучение остаётся теорией.

**Делай:** минимум 1-2 `exercises` в каждом tutorial (формат: question + hint).
**Не делай:** заканчивать tutorial словом «готово» без переноса в практику.

## Структурные стандарты

### Новый узел mindmap
6-вопросная схема (`what / why / when / impact / example / mistakes`)
обязательна. Подробности — `docs/content-rules.md`.

Дополнительно для AI-специфики:
- `example` — должен быть **запускаемым** (промпт, команда, фраза).
- `mistakes` — конкретное действие новичка, не «делать неправильно».

### Новый tutorial
Помимо стандартных полей (см. tutorials.js), для AI-обучения нужны:
- `level: 'beginner' | 'intermediate' | 'advanced'` — обязательно
- `outcomes[]` — что пользователь сможет ПОСЛЕ (концентрация на результате)
- `applyIn[]` — 2-4 реальных кейса для приземления
- `exercises[]` — минимум 2, по правилу 10 выше
- `pitfalls[]` — типичные ошибки на этой теме

### Новый library prompt
Шаблон с плейсхолдерами `{{snake_case}}` — пользователь подставляет свои данные.
Сам шаблон — иллюстрация **техники**, не «готовый ответ под одну задачу».

### Новый learning path
Цепочка node + tutorial + prompt в правильной последовательности.
Прогресс выводится автоматически из существующих источников.

## Anti-patterns AI-обучения

| Анти-паттерн | Почему плохо | Что делать вместо |
|---|---|---|
| «Спроси Claude X — получишь Y» | Не воспроизводится: модель отвечает по-разному | «Спроси X, ожидай ответ в формате Z» + критерий проверки |
| Учить только успешным промптам | Не формирует понимание «почему» | Начинать с плохого примера, затем правильный |
| Прятать лимиты | Пользователь сожжёт квоту и потеряет доверие | Лимиты — отдельная глава, обязательна |
| Опираться на одну модель | Привычка «всё на Opus», дорого | Учить выбору модели как навыку |
| «Готовый рецепт без понимания» | Не работает на смежной задаче | Принцип → пример → упражнение на своей |
| Заканчивать tutorial без exercises | Знание не приземляется | exercises обязательны |
| Игнорировать многоканальность | Пользователь не использует половину Claude | Покрывать vision/files/web/code |

---

## Когда применять эти правила

- При создании любого **нового узла** mindmap → пропускай через эти 10 правил
- При апгрейде **существующего узла** — проверь, не нарушает ли он правила
- При написании **новых tutorials** — выполняй обязательные структурные стандарты
- При ревью **library prompts** — техника, не «готовый ответ»

Skill `ai-pedagogy-architect` следует этим правилам по умолчанию.

## Модель «курс на узле» (node-course) — 2026-06-04

Новое поведение обучения. Каждый **конечный узел (лист)** mindmap может иметь
свой курс по своей теме. На листе с курсом в `DetailPanel` показывается кнопка
**«Узнать больше»** (ключи `detail.tutorialPass/Continue/Retake`), которая
открывает курс. Кнопка появляется только там, где курс есть; где курса нет —
не показывается.

**Стандарт длины — строго 6 шагов.** Любой курс = ровно 6 шагов:
- Тема большая (как Desktop) → группируй в 6 насыщенных шагов, не плоди 16.
- Тема маленькая → наполни до 6 содержательных шагов, без воды-паддинга.
- Цель: предсказуемая форма для пользователя (прогресс всегда из 6).

**Где живёт что:**
- Структура курса (nodeId, icon, level, steps:[{id}]) — `src/data/tutorials.js`.
- Контент (title/subtitle/whatItIs/approach/outcomes/applyIn/pitfalls/exercises +
  steps{id:{title,why,instructions[],validate,tip}}) — `src/locales/*/tutorials.json`.
- `nodeId` связывает курс с узлом через `tutorialByNodeId` (обратный индекс).

**Два уровня информации:**
- Подраздел/лист — лёгкая подсказка: поле `example` узла + кнопка «Попробовать в
  Claude» (уже есть). Это «как сделать + пример запроса».
- Лист с курсом — полноценный 6-шаговый курс по кнопке «Узнать больше».

**Не путать с маршрутами (Polut):** маршрут = горизонтальное путешествие через
МНОГО узлов; курс-узла = вертикальное погружение в ОДНУ тему листа.

**Раскатка:** каркас + стандарт — готовы; курсы наполняются ветка за веткой.
Эталон пилота — `project-files` (лист `p-files`, ветка Projects). Существующие
курсы с числом шагов ≠ 6 нормализуются к 6 по мере раскатки.
