# translate-to-finnish

Skill для качественного AI-перевода RU → FI с учётом:
1. Английского глоссария (термины остаются как есть)
2. Финских падежных окончаний на английских терминах
3. Конверсационного тона оригинала (без формализации)
4. Сохранения JSON-структуры, плейсхолдеров, markdown

## Когда триггерится

- Пользователь явно просит: «переведи на финский», «прогон locales/ru → locales/fi», «обнови финскую локаль».
- Файлы `src/locales/fi/*.json` устарели относительно `src/locales/ru/*.json` (timestamp или явный diff).
- Просьба добавить новую локаль ru→fi для конкретного контентного файла.

## Когда НЕ триггерится

- Запрос «переведи на английский» — используй другой skill (или прямой запрос с правилами).
- Файл вне `src/locales/ru/` — это либо UI-строки (которые уже переведены вручную), либо данные структуры (не переводятся).

## Inputs

- `source_file` — путь к RU JSON (например `src/locales/ru/nodes.json`)
- `target_file` — путь к FI JSON (по умолчанию `src/locales/fi/<имя>.json`)
- `glossary_file` (опционально) — путь к `src/locales/glossary.json` (по умолчанию авто-определяется)
- `batch_size` (опционально, для больших файлов) — сколько top-level ключей переводить за один промпт. По умолчанию 20.

## Outputs

- Обновлённый `target_file` с полным переводом всех значений из source. Структура (ключи) идентична source. Английские термины из глоссария — без изменений.

## Workflow

### Шаг 1. Загрузить глоссарий

Прочитай `src/locales/glossary.json`. Внутри — массив `terms` из ~120 английских терминов. Эти строки **НЕ** переводятся ни при каких условиях.

### Шаг 2. Загрузить source

Прочитай `source_file` (`locales/ru/<имя>.json`). Это валидный JSON с произвольной вложенностью. Все строковые значения — кандидаты на перевод (кроме тех, что в глоссарии).

### Шаг 3. Спланировать батчи

Если в файле > 30 top-level ключей — разбей на батчи по `batch_size`. Каждый батч переводи отдельным промптом, сохраняя структуру.

### Шаг 4. Перевод

Используй следующие правила для каждого батча:

#### Правила перевода

1. **Глоссарий не трогаем.** Любой термин из `terms` — оставляй ровно как есть, с тем же регистром:
   - ✅ `MCP` → `MCP`
   - ✅ `Claude Code` → `Claude Code`
   - ✅ `Prompt injection` → `Prompt injection`
   - ❌ НЕ переводи `Skills` в `Taidot`, `Tool use` в `Työkalujen käyttö` и т.п.

2. **Падежные окончания на глоссарных терминах** добавляй через двоеточие или дефис, по правилам финского:
   - Genitive: `MCP:n`, `Skills:n`, `Claude Coden`
   - Partitive: `Tool usea`, `Skillsiä`
   - Allative/illative: `MCP:hen`, `Claude Codeen`
   - Inessive/elative: `Skillsissä`, `MCP:ssä`
   - Adessive: `MCP:llä`, `Claude Codella`
   - Compound: `Skills-toiminto`, `MCP-palvelin`, `Tool use -periaate`

3. **Плейсхолдеры** сохраняй точно: `{n}`, `{done}`, `{total}`, `{query}`, `{{var}}`, `[варианты в квадратных скобках]`. Их содержимое не переводи (внутри плейсхолдера — это переменная, не текст).

4. **Markdown** сохраняй: `**жирный**`, `*курсив*`, ` ``` блоки ``` `, ссылки `[text](url)`. Переводи только видимый текст вне разметки.

5. **Code-блоки** (` ``` ... ``` `) и inline-код (`` `var` ``) — НЕ переводи. Это технические примеры (промпты, JSON-схемы, CLI-команды).

6. **Тон** — конверсационный, как в оригинале. Автор обращается к читателю на ты («ты»), даёт прямые советы, использует разговорные формулировки. На финском:
   - используй `sinä`-форму (не `te`)
   - короткие активные предложения
   - избегай канцелярита и излишней формальности
   - технические объяснения — кратко, без академического стиля

7. **Числа, проценты, единицы измерения** — оставляй формат как в источнике (`5×`, `+30-50%`, `200K-1M токенов`). Если в финском нужна другая пунктуация в числах (запятая vs точка как десятичный разделитель) — приводи к финскому стандарту.

8. **JSON-структура** не меняется: ключи остаются английскими, только значения переводятся. Если значение — массив строк, переведи каждую строку.

9. **Пустые строки** (`""`) оставляй пустыми. Не добавляй placeholder-перевод.

10. **Особые поля** в `nodes.json` / `tutorials.json`:
   - `title` — обычно 1-3 слова, иногда содержит глоссарные термины
   - `what` / `why` / `when` / `impact` — 1-2 предложения, конверсационный стиль
   - `example` — часто конкретный промпт-пример, может содержать `[плейсхолдеры]`
   - `mistakes` — типичная ошибка, формулировка «сделать-X — последствие-Y»

### Шаг 5. Валидация перевода

После перевода батча проверь:

- [ ] JSON валидный (распарсится без ошибок)
- [ ] Все ключи из source присутствуют в output
- [ ] Все термины из глоссария присутствуют в output (regex-проверка)
- [ ] Нет «забытых» русских фрагментов (regex `[А-Яа-я]` в значениях)
- [ ] Плейсхолдеры `{...}` совпадают по списку с source

Если валидация провалена — повтори перевод этого батча с указанием конкретной проблемы.

### Шаг 6. Сохранить result

Запиши в `target_file`. Используй pretty-print JSON (`indent: 2`), завершающий newline.

### Шаг 7. Отчёт

Покажи пользователю:
- Сколько ключей переведено
- Сколько глоссарных терминов сохранилось
- Если были fallback'и или сомнительные места — список с указанием пути в JSON
- Команду для запуска lint: `npm run lint:data`

## Антипаттерны (что НЕ делать)

- ❌ Переводить термины из глоссария «потому что они часто употребляются на финском в переводе» — НЕТ. Глоссарий — закон.
- ❌ Менять структуру JSON (даже если кажется, что «так лучше»).
- ❌ Добавлять префиксы / суффиксы / поясняющие комментарии к переводу — только чистый перевод значения.
- ❌ Переводить значения внутри code-блоков или inline-кода.
- ❌ Терять или добавлять плейсхолдеры — это сломает рендеринг.
- ❌ Менять тон на более формальный «для надёжности» — теряется голос автора.

## Расширения для будущих локалей

Если потребуется перевод на другой язык (например, шведский, английский):
1. Создай `skills/translate-to-<lang>/SKILL.md` по этому шаблону.
2. Адаптируй правило падежных окончаний под целевой язык (для EN — не нужны; для шведского — другая система).
3. Адаптируй тон под культурную норму («ты» vs «вы», формальность).
4. Глоссарий остаётся общим — `src/locales/glossary.json`.

## Связано

- `src/locales/glossary.json` — источник правды для do-not-translate
- `src/locales/ru/*.json` — source (читать)
- `src/locales/fi/*.json` — target (писать)
- `scripts/lint-data.mjs` — валидация completeness и glossary-check
- `docs/maintenance.md` — каденс обновления локалей
