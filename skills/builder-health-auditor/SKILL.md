# builder-health-auditor

> Skill для диагностики «почему запуск Builder отработал, но результат не тот»
> (особенно доставка в Telegram / реальный запуск). Системная проверка
> работоспособности по слоям: схема → сервер → доставка.

---

## Назначение

Когда пользователь говорит «запустил, статус completed, но сообщение/результат не
пришёл» — пройти по слоям и найти, где обрывается цепочка.

**Когда вызывать:**
- «Telegram не приходит, хотя всё зелёное»
- «Реальный запуск завершился, но результата нет»
- «Узел completed, а доставки не было»
- Любой аудит работоспособности Builder

---

## Принцип: статус узла ≠ доставка

Зелёный «completed» означает лишь «шаг отработал без исключения». Доставка
(Telegram/email) — отдельный факт. Поэтому в edge-функции «не доставлено»
ОБЯЗАНО помечаться `status:'failed'` (красным), а не зелёным. Если видишь зелёный
узел без доставки — первый подозреваемый: **на сервере старая версия функции**.

---

## Чек-лист диагностики (по слоям)

### 1. Схема (frontend)
- Все узлы соединены? `User Input` ведёт к агенту? (pre-run валидация предупреждает).
- У `Telegram`-узла задан **адрес чата** (поле «Доставка»)? Пустой → доставки нет.

### 2. Конфигурация доставки (самые частые ошибки)
- **chat_id неверный.** `@имя_бота` — это сам бот, НЕ получатель. Нужен:
  - числовой ID личного чата (узнать: написать боту → `/botТОКЕН/getUpdates` → `chat.id`), или
  - `@channel`, где бот — администратор.
- Пользователь **нажал Start** у бота (бот не пишет первым тому, кто его не запускал).
- Токен бота **актуальный** (не отозванный в @BotFather).

### 3. Сервер (edge functions) — частая причина «зелёное, но молча»
- **Функция развёрнута в актуальной версии?** Код в репозитории ≠ то, что крутится
  на Supabase. После правок ОБЯЗАТЕЛЬНО:
  ```
  supabase functions deploy builder-execute
  supabase functions deploy builder-connect-key
  ```
- Секрет шифрования установлен: `BUILDER_KEY_ENCRYPTION_SECRET`.
- Токен Telegram реально прочитан: в `builder-execute` запрос
  `builder_api_connections` provider='telegram' is_active=true.

### 4. Логи запуска (источник правды)
Открыть панель «Выполнение» → прочитать строку Telegram-узла:
- `Sent to Telegram ✓` → доставлено.
- `Telegram did not deliver: chat not found` → неверный chat_id.
- `Telegram bot not connected` → токен не подключён/не прочитан.
- `No chat ID set` → пустое поле адреса.
- Нет строки про Telegram вообще → **старый деплой** (нет кода доставки).

---

## Типовой вердикт «completed, но не пришло»

1. chat_id = `@имя_бота` → заменить на числовой ID. (90% случаев)
2. Старый деплой `builder-execute` → переразвернуть.
3. Не нажат Start у бота → нажать.

---

## Outputs

- Точная причина (по логам) + конкретный шаг исправления.
- Если нужен код — правки в `supabase/functions/builder-execute/index.ts`
  (честные статусы) и `src/builder/services/connectionRules.js` (pre-run warnings).
- После правок сервера — напомнить про `supabase functions deploy`.
