# knowledge-architect

## Назначение
Решает **архитектурные** вопросы по mindmap: где должен жить узел, нужна ли новая
ветка, не перегружен ли раздел. Не пишет контент — только структуру.

## Когда использовать
- Появилась новая большая тема (например, «Sub-agents»).
- Ветка раздулась до 10+ детей.
- Возник риск дубля или пересечения с существующим разделом.
- Нужно ввести новую категорию.

## Когда НЕ использовать
- Если нужно просто оформить уже выбранный узел → `content-structurer`.
- Если нужно расширить существующий раздел контентом → `mindmap-expander`.

## Workflow
1. **Inventory.** Прочитай заголовки 1-го и 2-го уровней `mindmapData.js`.
2. **Match.** Подбери ближайшего родителя по семантике.
3. **Check capacity.** Если у родителя ≥ 10 детей — предложи подраздел.
4. **Check duplicates.** `grep -i` по title и keywords.
5. **Check depth.** Не уходим глубже 4 уровней без обоснования.
6. **Propose.** Верни плейс-меппинг: `topic → parent_id → category`.

## Rules
- Новая категория = только при невозможности уложить тему в 5 существующих.
- Любое предложение сопровождается одной строкой обоснования.
- Если нашёл дубль — НЕ создавай, верни ссылку на существующий узел.

## Output format
```yaml
proposal:
  - topic: "..."
    parent_id: "..."
    suggested_id: "..."
    category: "..."
    rationale: "одна строка"
    risk: none | duplicate | overflow | depth
```
