# news-watcher

## Назначение
Поддерживать Claude Atlas в актуальном состоянии. Anthropic выкатывает фичи
быстрее, чем человек успевает отслеживать. Этот skill — автоматическая
сигнализация о том, что Atlas начал отставать.

## Принцип работы

1. **Читает официальные источники** (через WebFetch / WebSearch tools):
   - https://www.anthropic.com/news — новости Anthropic
   - https://docs.anthropic.com/en/release-notes/ — release notes API/моделей
   - https://docs.anthropic.com/en/docs/ — основная документация
   - https://claude.ai/changelog (если доступен) — изменения claude.ai
   - https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md — Claude Code
2. **Сравнивает** найденные темы с текущими узлами `mindmapData.js`.
3. **Категоризирует** изменения:
   - `new-feature` — новая возможность, которую Atlas не покрывает
   - `version-bump` — обновлена модель / тариф / лимит (требует ревизию deprecate-watch узлов)
   - `breaking` — изменение, ломающее существующие узлы (например, фича удалена)
   - `clarification` — официальное уточнение поведения
4. **Предлагает действия**:
   - Добавить новый узел (с предложением parent_id, category, level)
   - Обновить существующий (точный узел id и поле)
   - Пометить deprecate-watch (узел может устареть)

## Когда запускать

| Случай | Каденс |
|---|---|
| Регулярная проверка | Раз в неделю (по cron / scheduled task) |
| После крупного анонса Anthropic | Сразу |
| Раз в квартал | Полный прогон с `since-date = 90 дней назад` |
| Подготовка к major-обновлению Atlas | Перед началом контент-спринта |

## Workflow

### Шаг 1. Установить временной диапазон
- По умолчанию: последние 7 дней
- Если `since-date` задан — от него

### Шаг 2. Получить материалы из источников
- WebFetch на каждый из URL списка выше
- Парсить даты публикации, отфильтровать по диапазону
- Сохранить заголовки + краткие описания

### Шаг 3. Извлечь темы
Из каждой новости / changelog-записи выписать темы:
- Модели (новая версия, изменения возможностей)
- Тарифы / лимиты (новые планы, изменения квот)
- Платформы (новые приложения, расширения)
- Фичи (vision, search, computer use — что добавилось/изменилось)
- Безопасность / privacy (новые настройки, изменения policy)

### Шаг 4. Сопоставить с текущим Atlas
Грep по `mindmapData.js`:
- Тема упоминается → возможно нужно обновление узла
- Темы нет → возможно нужен новый узел
- Тема устарела (фича удалена) → пометить узел

### Шаг 5. Сформировать отчёт
Структурированный список:

```yaml
period: "2026-01-15 → 2026-01-22"
sources_checked: 5

changes:
  new_features:
    - topic: "Computer use 1.5 — улучшения латентности"
      source: "https://www.anthropic.com/news/..."
      proposed_action: "Обновить узел cap-computer: добавить упоминание latency"

    - topic: "Новый MCP-сервер для X"
      source: "https://..."
      proposed_action: "Добавить узел m-X в готовые серверы под m-ready"

  version_bumps:
    - topic: "Sonnet 4.7 → 4.8"
      source: "https://docs.anthropic.com/en/release-notes/..."
      proposed_action: "Обновить b-models. Проверить pl-models — доступность по тарифам"

  breaking:
    - topic: "Старый API endpoint удалён"
      source: "https://..."
      proposed_action: "Найти упоминания в Atlas, пометить deprecate"

  clarifications:
    - topic: "Уточнение по prompt caching TTL"
      source: "https://..."
      proposed_action: "Обновить cap-caching: добавить deprecate-watch с датой"
```

### Шаг 6. Запись в backlog
Добавить пункты в `tasks/backlog.md` секция «Контентный план / High priority»:
- Каждый `proposed_action` — отдельная строка
- С указанием источника (URL)
- С пометкой даты обнаружения

### Шаг 7. (Опц.) Открыть draft PR
Если интегрирован git workflow — создать branch и черновик PR с предложенными правками. Не мержить — пусть человек ревьюит.

## Rules

- **Не выдумывать.** Если в источнике нет точной информации — пиши «требует подтверждения» с пометкой source-URL.
- **Не предлагать удаление узлов** без явного breaking change — только `deprecate-watch` пометку.
- **Не дублировать** уже существующие записи в backlog — сначала grep, потом запись.
- **Источник обязателен** для каждого пункта — без URL не публикуй.
- **Не доверять неофициальным источникам** (блоги, Twitter) — только Anthropic-owned ресурсы.

## Output format

```markdown
## News-watcher отчёт от 2026-XX-XX

**Период:** YYYY-MM-DD → YYYY-MM-DD
**Источников проверено:** N

### Critical (требует немедленной правки)
- [ ] <тема>: <предложенное действие> (<source URL>)

### Important (стоит включить в ближайший спринт)
- [ ] ...

### Nice-to-have
- [ ] ...

### Deprecate-watch обновления
- [ ] <узел id>: <причина пометки> (<source>)
```

## Anti-patterns

- Запускать каждый день — большинство недель Anthropic ничего не релизит
- Принимать все предложения без ревью — модель может ошибиться в интерпретации
- Игнорировать deprecate-watch — узлы накопят устаревший контент
- Полагаться только на этот skill — крупные изменения политики/тарифов могут быть в блогах вне основных источников
