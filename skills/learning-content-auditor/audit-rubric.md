# Audit Rubric — 7 осей проверки обучающего контента Atlas

Каждый узел / туториал / шаг проходит по 7 осям. На каждой — пройдено / частично / провалено + цитата + предложение.

---

## Ось 1. Ясность языка (voice-guide.md)

### Проверка по 6 принципам voice-guide
- [ ] **Пример первым, концепт после.** В первых 2 предложениях `what` есть конкретный пример из жизни?
- [ ] **«Ты», не «команды».** Обращение к одному человеку, не «компаниям использующим X»?
- [ ] **Знакомые якоря.** Google Photos / Notion / Slack / Excel вместо «vector embeddings» / «HNSW»?
- [ ] **Человеческие метрики.** «4 часа → 30 минут» вместо «+30% productivity»?
- [ ] **Снят страх.** Адресуется типовое опасение («AI напишет generic», «меня заменят»)?
- [ ] **Maturity stages как личный путь.** «Через 3 месяца ты ...» вместо «Stage 1→2 transition»?

### Анти-паттерны (если есть — P0)
- ❌ «Это позволяет командам ...»
- ❌ «В современных AI-системах ...»
- ❌ «В большинстве случаев ...»
- ❌ «Архитектурно правильный подход ...»
- ❌ «Critical для production-ready ...» (англицизм без перевода)
- ❌ Перечисление паттернов без примера каждого

### Запах жаргона
Поиск без объяснения / якоря:
- LLM, embedding, vector, tokenizer, attention, transformer
- RAG (если упомянут впервые без расшифровки)
- inference, training, fine-tuning, RLHF
- agent, orchestration, multi-agent (если без примера)
- HNSW, ANN, BM25, dense / sparse retrieval

**Правило:** жаргон допустим если он расшифрован якорем в той же фразе. «Embedding — это как Google Photos, который понимает что на фотке «коты» без подписи» — ОК. «Embedding-based retrieval с HNSW индексом» — НЕ ОК.

## Ось 2. Структура узла

### Полнота 6 полей
- [ ] `what` — 2-3 предложения, что это
- [ ] `why` — 1-2 предложения, зачем именно тебе
- [ ] `when` — сигналы из жизни «когда понять что пора?»
- [ ] `impact` — до/после в часах/долларах/самочувствии
- [ ] `example` — конкретный workflow / пример с шагами
- [ ] `mistakes` — антипаттерн с последствием «делаешь X → получишь Y»

### Разделение полей
- [ ] `what` НЕ содержит «зачем» (это поле `why`)
- [ ] `why` НЕ содержит «когда» (это поле `when`)
- [ ] `example` — РЕАЛЬНЫЙ кейс с цифрами и шагами, не пересказ `what`
- [ ] `mistakes` — конкретные «делаешь так — будет плохо», не общие предупреждения

### Длина
- [ ] Узел читается за 60-90 секунд (примерно 200-400 слов суммарно по полям)
- [ ] Поле `example` ≤ 10 строк (если больше — выносить в туториал)
- [ ] Нет «стен текста» в одном поле (≥ 5 предложений без абзаца → разбить)

## Ось 3. Связность (inline-links)

### Cross-link покрытие
- [ ] Первое упоминание концепта который есть как отдельный узел → `[[node:X|label]]`
- [ ] Упоминание готового промпта → `[[prompt:X|...]]` (не «См. FAB»)
- [ ] Упоминание туториала → `[[tutorial:X|...]]` (не «есть туториал про X»)
- [ ] Списки 5+ дочерних узлов → каждый элемент — ссылка

### Анти-паттерны связности
- ❌ «См. FAB → ...» / «открой Floating Action Button»
- ❌ «Подробнее в разделе X» без ссылки
- ❌ «Есть готовый промпт для этого» без ссылки
- ❌ Перечисление концептов без ссылок на их узлы

### Перебор
- ❌ Больше 3 ссылок в одном коротком поле (превращается в синюю стену)
- ❌ Ссылка на узел которого нет (битая ссылка)

## Ось 4. Опыт обычного человека (persona walkthrough)

### Тест «глазами персоны»
Прочитай узел КАК выбранная персона (designer / marketer / pm / ops-manager / ordinary-human). Фиксируй:

- [ ] **Первое предложение** — узнаёт ли персона себя?
- [ ] **Жаргон без якоря** — где спотыкается?
- [ ] **Предполагаемые знания** — что узел молча подразумевает?
- [ ] **Релевантность примера** — пример подходит профессии персоны?
- [ ] **Финал** — после прочтения персона знает что сделать завтра?

### Запах «не для тебя»
- ❌ Пример исключительно про код когда узел в разделе marketing/design
- ❌ Метафоры из мира engineering для не-engineering персон
- ❌ Расчёты «$/token» когда персона не покупает API
- ❌ Имена технических людей (Karpathy, Sutskever) как якоря без объяснения

## Ось 5. Snackable knowledge (TikTok-mind)

### Sканируемость
- [ ] Bold-выделения ключевых слов в длинных полях?
- [ ] Списки с буллетами вместо абзацев параграфов?
- [ ] Короткие предложения (≤ 20 слов) преобладают?
- [ ] Цифры и метрики вынесены отдельной строкой, не вписаны в текст?

### Тест «первые 2 строки решают»
- [ ] Прочитал первые 2 строки `what` — понял основную идею
- [ ] Если нет — узел не выживет в TikTok-длине внимания (это ~60% юзеров)

### Mobile-readability
- [ ] Длинные параграфы (≥ 4 строки) есть? — переразбить
- [ ] Code-блоки / `<pre>` ≤ 8 строк на экране?
- [ ] Списки с подзаголовками вложенными ≤ 2 уровней?

## Ось 6. Multi-modal hooks

### Якоря для разных типов восприятия
- [ ] **Визуальный читатель** — есть конкретная картинка/сцена («представь Notion с папками …»)?
- [ ] **Кинестетический** — есть «попробуй сделать X прямо сейчас» / next-action?
- [ ] **Логический** — есть структурный принцип / правило / формула?
- [ ] **Социальный** — есть «как это меняет работу в команде» / общение с коллегами?

### Якорь = знакомый объект
- [ ] Google Photos — для embeddings / image AI
- [ ] Gmail — для классификации / автоответов
- [ ] Notion / Slack — для team workflow / контекст
- [ ] Excel-формула — для structured вычислений
- [ ] Spam-фильтр — для классификации
- [ ] Wikipedia — для knowledge base
- [ ] Поисковая выдача — для retrieval / RAG

## Ось 7. Future-proof (горизонт 1-5 лет)

### Riski устаревания
- [ ] Узел привязан к конкретной версии модели (Sonnet 3.5, Opus 4)? — риск
- [ ] Узел про конкретную UI-кнопку в claude.ai? — высокий риск (UI меняется)
- [ ] Узел про конкретный pricing-tier? — риск
- [ ] Узел опирается на «текущий context window 200k»? — высокий риск

### Принципы выше частностей
- [ ] Можно ли переформулировать через **принцип** вместо текущей реализации?
- [ ] Если Anthropic выкатит multimodal-by-default через 2 года — узел всё ещё актуален?
- [ ] Если MCP станет mainstream — узел учитывает это или говорит «MCP — модно, попробуйте»?

### Тренды на которые проверяем (см. trends-2026-2030.md)
- [ ] Voice-first interfaces — узел работает если AI = voice agent?
- [ ] Autonomous agents — узел учитывает что AI может действовать без supervision?
- [ ] Multi-modal default — узел не привязан только к text I/O?
- [ ] Local-first / on-device AI — узел работает в офлайн-сценариях?
- [ ] AI-native organizations — узел масштабируется на «вся команда работает с AI»?

## Сводный score узла

После 7 осей считаем «общую готовность к обычному человеку»:

| Ось | Вес | Score 0-3 |
|-----|-----|-----------|
| 1. Ясность языка | ×3 | 0 / 1 / 2 / 3 |
| 2. Структура | ×2 | 0 / 1 / 2 / 3 |
| 3. Связность | ×1 | 0 / 1 / 2 / 3 |
| 4. Опыт персоны | ×3 | 0 / 1 / 2 / 3 |
| 5. Snackable | ×2 | 0 / 1 / 2 / 3 |
| 6. Multi-modal hooks | ×1 | 0 / 1 / 2 / 3 |
| 7. Future-proof | ×2 | 0 / 1 / 2 / 3 |

**Max = 42 балла.** Узел считается «99% готов для обычного человека» если:
- Score ≥ 36 (85%+)
- Нет ни одной оси с score = 0 (нет критических провалов)
- Тест «бабушка / соседский подросток» пройден (см. SKILL.md)

### Приоритеты по score
- **Score ≤ 18 (≤ 43%)** → P0, переписать целиком
- **Score 19-27 (45-64%)** → P1, точечная правка нескольких полей
- **Score 28-35 (66-83%)** → P2, шлифовка, опционально
- **Score ≥ 36 (≥ 85%)** → не трогать, эталон
