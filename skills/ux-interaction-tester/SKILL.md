# ux-interaction-tester

## Назначение

«Профессионально опытный тестер» по интерактивному UX — не визуалист
и не контент-педагог. Думает в категориях:

- **Movement** — могу ли я пройти задачу за минимум кликов и не
  заблудиться?
- **Back-flow** — если я ушёл не туда, могу ли вернуться без потери
  контекста?
- **Predictability** — поведение элементов соответствует моим
  ожиданиям как пользователя?
- **Recovery** — есть ли возможность отменить случайное действие?
- **Discoverability** — могу ли я найти нужную функцию без подсказки?

Главный приоритет — **back navigation между модальными окнами**.
Каждый клик внутрь должен иметь явный «обратный билет».

## Когда использовать

- После добавления нового модального окна / нового workflow
- Перед публичным релизом
- При жалобах «не понимаю как закрыть» / «не вижу как вернуться»
- Раз в квартал regular audit

## Когда НЕ использовать

- Визуальный дизайн (цвета, типографика) → `accessibility-review`
- Аудит обучающего контента → `learning-content-auditor`
- Языковая правильность → `*-language-pedagogue`

## Workflow

1. Открыть приложение в Preview MCP (если возможно)
2. Пройти по чек-листу из `interaction-rubric.md`
3. Документировать каждое нарушение с конкретным сценарием
   воспроизведения и предложением фикса
4. Приоритизировать P0 (тупик / data loss) / P1 (раздражает) / P2 (полировка)
5. Сохранить отчёт в `tasks/ux-audit-<дата>.md`

## 6 категорий проверки

### N. Navigation (как пройти forward)
- Триггеры явные и единообразные?
- Mouse + keyboard работают одинаково?
- Hash-роутинг сохраняет состояние при refresh?
- Deep-link к любому окну работает?

### B. Back-flow (как вернуться) — **главный приоритет**
- ESC закрывает текущее окно?
- Клик-вне-окна закрывает (где это уместно)?
- Есть ли visible «Назад» / «Закрыть» кнопка?
- При переходе из A → B возможен ли возврат в A?
- Сохраняется ли state при back-navigation?
- Browser back-button работает?

### F. Focus management
- При открытии модала focus уходит внутрь?
- Tab-trap внутри открытого модала?
- При закрытии модала focus возвращается на trigger?
- Скрин-ридер озвучивает изменения?

### Fb. Feedback (даёт ли система знать что произошло)
- Loading states при долгих операциях?
- Success/error состояния после действий?
- Disabled-кнопки имеют tooltip «почему disabled»?
- Optimistic UI vs ждущий UI?

### D. Discoverability
- Главные функции достижимы за ≤ 2 клика?
- Hidden features имеют hint?
- Onboarding для новых юзеров?

### E. Errors & recovery
- Confirmation dialog для destructive actions?
- Undo для случайных удалений?
- Network error handling?
- Forms сохраняют ввод при ошибке?

Детальный чеклист (40+ пунктов) — в `interaction-rubric.md`.

## Приоритизация

| P | Что | Пример |
|---|-----|--------|
| **P0** | Пользователь застрял или потерял данные | Модал без × / ESC, форма теряет ввод при ошибке |
| **P1** | Раздражает, но возможно сделать задачу | Нет «назад» в стеке модалов, ESC не работает |
| **P2** | Полировка | Анимация задержана, focus не возвращается на trigger |

## Output контракт

`report-template.md` — формат отчёта. Каждое нарушение:
- ID шага (например `N.modal-open-3`)
- Категория (N/B/F/Fb/D/E)
- Приоритет (P0/P1/P2)
- Сценарий воспроизведения (3-5 шагов)
- Текущее поведение
- Ожидаемое поведение
- Предложение фикса
- Affected files (компоненты)
