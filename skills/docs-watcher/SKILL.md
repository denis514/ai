# docs-watcher (реакция на изменения документации)

## Когда использовать

После того как `scripts/docs-watcher.mjs` (раз в неделю или вручную) обнаружил
изменения в официальной документации Claude и записал дифф в `tasks/backlog.md`
под заголовком `## 📄 docs-watch: документация изменилась — <дата>`.

Сторож только сигналит. Этот скилл — **ручной шаг разбора**: превратить дифф
в правки узлов Atlas. Реакция выбрана пользователем: «сигнал + черновик правок»,
не авто-правка — значит правки вносятся осознанно, с проверкой.

## Алгоритм

1. **Прочитать дифф** в `tasks/backlog.md` (секция с сегодняшней датой) и при
   необходимости полный текст в `docs/docs-watch/snapshots/<slug>.md`.
2. **Классифицировать** каждое изменение:
   - `new-feature` — новая возможность → новый узел (6-вопросная схема).
   - `changed` — поведение/меню изменилось → правка `what/when/example` узла.
   - `removed` / `deprecated` — фича убрана → пометить узел в `tasks/backlog.md`
     статусом `deprecate` (не удалять молча, см. CLAUDE.md §8).
   - `cosmetic` — переформулировка без сути → игнор.
3. **Найти целевой узел** по `atlasHint` из диффа и поиском по `id`/`title`
   в `src/locales/ru/nodes.json`. Дубли не плодить.
4. **Внести правки** на русском в `src/locales/ru/nodes.json`; затем перевести
   в `en`/`fi` (или пометить задачу на перевод). Идентификаторы — латиница.
5. **Прогнать** `node scripts/sync-whats-new.mjs` — лейблы «новое/обновлено».
6. **Очистить** обработанную секцию из `tasks/backlog.md`.
7. **Build** `npm run build`. Для чистого контента барьер качества не нужен
   (CLAUDE.md §15), достаточно build + sync.

## Границы

- Не трогать `scripts/docs-watcher.mjs` и `state.json` руками — это движок сторожа.
- Не добавлять страницу в наблюдение здесь; это правка `WATCH` в скрипте
  (см. `docs/docs-watch/README.md`).
- Если изменение касается денег/лимитов/приватности — отразить простыми словами
  (CLAUDE.md §14b) и сверить с `deprecate-watch` узлами.
