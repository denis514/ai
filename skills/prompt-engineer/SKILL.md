# prompt-engineer

## Назначение
Гарантирует, что любой промпт в проекте написан по единым правилам и предсказуемо
работает на разных моделях Claude.

## Структура промпта (обязательная)
```
# Роль
Ты — <конкретная роль>.

# Контекст
<что модель должна знать о ситуации>

# Задача
<одно действие, конкретно>

# Ограничения
- …

# Формат вывода
<markdown / json / список / иное>
```

## Workflow
1. **Распознай тип.** One-shot / system prompt / агентный / few-shot.
2. **Назначь роль** конкретно (не «ассистент», а «senior UX-аудитор»).
3. **Изолируй задачу.** Одно действие на промпт.
4. **Сформулируй формат.** Что именно должно прийти на выходе.
5. **Добавь ограничения.** Что НЕ делать (часто важнее, чем что делать).
6. **Прогони чек-лист**:
   - [ ] роль конкретна
   - [ ] задача в одном действии
   - [ ] формат вывода однозначен
   - [ ] есть антипаттерны
   - [ ] плейсхолдеры в `{{snake_case}}`

## Rules
- Никаких «будь полезным» / «ответь подробно» — это шум.
- Few-shot примеры — только если без них модель ошибается.
- Если промпт длиннее 30 строк — он, вероятно, делает 2 задачи. Разбей.
- Все плейсхолдеры — `{{double_braces_snake_case}}`.

## Output format
```markdown
## Промпт
<готовый текст>

## Что улучшено (если рецензия)
- …
```
