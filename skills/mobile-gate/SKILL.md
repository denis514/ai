# mobile-gate

> Барьер мобильной версии. Группа узких ревьюеров по адаптиву → проверка на
> реальной мобильной ширине (скриншот) → судья. Запускается ПОСЛЕ десктопной
> вёрстки, ПЕРЕД продом. На BLOCK мобильные дефекты в прод не уходят.

---

## Назначение

Десктоп и мобайл ломаются по-разному. Этот гейт ловит то, что не видно на
широком экране: горизонтальный скролл, обрезанный контент, наезжающие элементы,
крошечные тач-цели, hover-only интерактив, нечитаемый текст. Дополняет
`quality-gate` (тот — корректность/безопасность; этот — адаптив).

**Когда вызывать:**
- После любой правки UI (`src/**/*.jsx`, `*.css`) перед `git push`, если менялась
  вёрстка/стили.
- По запросу «проверь мобильную версию» / «прогони mobile-gate».

**Режим:** on-demand. Строгость: BLOCK только на «ломающих мобайл» дефектах
(см. рубрику). Косметика — замечания.

---

## Целевые экраны (минимум)

- **360×800** (узкий Android), **390×844** (iPhone), **414×896** (крупный),
  планшет **768×1024** — опционально.
- Проверка и в **светлой, и в тёмной** теме.

---

## Рубрика серьёзности

**BLOCK (ломает мобайл):**
- 🔴 **Горизонтальный скролл** страницы/контейнера (контент шире вьюпорта).
- 🔴 **Обрезанный/недоступный** контент или действия (кнопка/текст уходит за экран,
  модалка не закрывается, меню не открывается).
- 🔴 **Наезжающие/перекрывающие** элементы; нечитаемый текст (<12px для основного).
- 🔴 **Тап-цели < 40×40px** у ключевых действий (закрыть, отправить, навигация).
- 🔴 **Hover-only** интерактив без тач-эквивалента (на тач нет hover).
- 🔴 Фиксированные элементы перекрывают контент/ввод; не учтён safe-area (вырез).

**REMARK (не блок):** неоптимальные отступы, мелкие выравнивания, «можно плотнее»,
микро-анимации, не критичная плотность.

Судья (`code-judge`) ставит BLOCK при ≥1 подтверждённом дефекте из первой группы.

---

## Группа ревьюеров (по сегментам)

| Сегмент | Что проверяет | Кто |
|---|---|---|
| Адаптивная вёрстка | брейкпоинты, overflow-x, ширины, перенос, модалки/шторки | `mobile-responsive-reviewer` |
| Тач-взаимодействие | размер тапа, hover-only, жесты, скролл, фокус | `mobile-interaction-reviewer` |
| Доступность | контраст, размер шрифта, viewport-meta, focus-order | `accessibility-review` |
| Производительность | вес бандла, тяжёлые анимации/тени на мобайле | `performance-auditor` |
| Арбитр | PASS/BLOCK + правки | `code-judge` |

Запускать только релевантных сегментам diff (правка только CSS → вёрстка+a11y).

---

## Конвейер (review → verify(screenshot) → judge)

1. **Сбор**: какие компоненты/стили изменены; на каких экранах это видно.
2. **Ревью кода** (параллельно по сегментам) — находки с severity, файл/строка, правка.
3. **Проверка на реальной ширине (обязательна для BLOCK-кандидатов):**
   - Запустить приложение (preview) и через mobile-viewport снять скриншоты на
     **390×844** (и 360×800 при сомнении), в светлой и тёмной теме.
   - Инструменты: Claude Preview (`preview_resize` → 390×844, `preview_screenshot`)
     или Claude in Chrome (`resize_window`). Проверить: нет горизонтального
     скролла, всё в кадре, тап-цели крупные, меню/модалки открываются.
   - Скриншот превращает «подозрение» в подтверждённый BLOCK или снимает его.
4. **Судья**: агрегирует, применяет рубрику → PASS / BLOCK + обязательные правки.

> Если запустить превью нельзя — отметить в выводе «визуально не проверено» и
> оценивать строго по коду (не выдавать ложный PASS).

## Формат вывода

```
📱 MOBILE GATE — <PASS ✅ | BLOCK ⛔>

Экраны: 390×844, 360×800 · темы: светлая/тёмная · скриншот: ✅/нет
Затронуто: <сегменты>

⛔ Блокеры (исправить до пуша):
  1. [сегмент] файл:строка — суть (на каком экране ломается). Правка: …
💬 Замечания:
  • …

Вердикт судьи: <одно предложение>
```

На **BLOCK**: НЕ пушить, исправить, прогнать заново.
