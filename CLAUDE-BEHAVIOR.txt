================================================================================
              КАК CLAUDE БУДЕТ ВЕСТИ СЕБЯ В ПРОЕКТЕ "CLAUDE ATLAS"
                        AI-NATIVE KNOWLEDGE SYSTEM
================================================================================

Этот документ — операционная инструкция. Описывает, что именно Claude делает,
когда работает в этом репозитории, и какие правила соблюдает.


================================================================================
0. ПРИНЦИП НОМЕР ОДИН
================================================================================

При открытии папки Claude сначала читает CLAUDE.md, затем tasks/current.md,
и только потом приступает к работе. Без этих двух файлов любое действие
считается небезопасным.


================================================================================
1. ЧТО ВООБЩЕ ЗА ПРОЕКТ
================================================================================

Claude Atlas — это AI-native knowledge system о Claude и его экосистеме.
Одновременно:
  - AI handbook (справочник)
  - interactive mindmap (визуальная карта)
  - knowledge base / wiki
  - learning platform (микро-уроки)
  - площадка AI workflows

UI вторичен. Главное — архитектура знаний и AI infrastructure.

Технический стек зафиксирован: React 18 + Vite + чистый CSS + Hugeicons (free).
Без TypeScript, Tailwind, CSS-in-JS, state managers, UI kits.
Иконки — только через <Icon name="..." /> из src/components/Icon.jsx
(семантические kebab-case имена). Эмодзи в JSX и в src/data/* запрещены.

================================================================================
3. КАК CLAUDE РЕАГИРУЕТ НА ТИПИЧНЫЕ ЗАПРОСЫ
================================================================================

  Запрос пользователя              Что Claude делает
  -------------------              -----------------

  "Добавь узел про X"              1. claude-expert проверяет факт
                                   2. knowledge-architect ищет parent
                                   3. content-structurer заполняет 6 полей
                                   4. mindmap-expander правит mindmapData.js
                                   5. tasks/current.md обновляется

  "Расширь раздел Y"               1. читает текущий раздел
                                   2. knowledge-architect: нужен ли подраздел
                                   3. 3-5 кандидатов через content-structurer
                                   4. согласует с пользователем
                                   5. mindmap-expander вносит правки

  "Создай AI workflow для Z"       1. ai-workflow-builder делает YAML
                                   2. mcp-specialist проверяет MCP-части
                                   3. automation-architect — триггер/kill-switch
                                   4. потенциальный узел в категории "агенты"

  "Объясни фичу Claude"            1. claude-expert даёт факт + пример + ошибку
                                   2. проверяет наличие узла в mindmap
                                   3. предлагает добавить, если узла нет

  "Напиши/улучши промпт"           1. prompt-engineer строит по шаблону
                                      Роль / Контекст / Задача / Ограничения / Формат
                                   2. переиспользуемый → src/data/prompts.js
                                   3. разовый → prompts/<action>.md

  "Поправь UI"                     1. react-knowledge-ui (единственный, кто
                                      имеет право трогать src/components/)
                                   2. accessibility-review после изменений
                                   3. упоминает npm run build для проверки

  "Что сейчас в работе?"           1. читает tasks/current.md, backlog.md, roadmap.md
                                   2. кратко: активное, в очереди, недавнее
                                   3. ничего не выдумывает

4. 11 SKILLS И ИХ ЗОНЫ ОТВЕТСТВЕННОСТИ
================================================================================

  knowledge-architect    Куда положить узел, нужна ли новая ветка
  ai-system-designer     Как собрать AI-решение из примитивов Claude
  claude-expert          Факты про Claude (модели, контекст, лимиты)
  prompt-engineer        Создание и ревью промптов
  react-knowledge-ui     Правки UI-слоя (только UI)
  mindmap-expander       Безопасная запись в mindmapData.js
  ai-workflow-builder    Многошаговые AI-сценарии
  mcp-specialist         Model Context Protocol
  automation-architect   Расписания, хуки, фоновые задачи
  content-structurer     6-вопросная схема узла (what/why/when/impact/example/mistakes)
  accessibility-review   WCAG-чек UI-изменений

ПРАВИЛО: один skill = одна зона. Skills не вызывают друг друга напрямую —
оркестрируется на уровне workflow.


================================================================================
5. СХЕМА УЗЛА MINDMAP (ОБЯЗАТЕЛЬНАЯ)
================================================================================

Каждый узел в src/data/mindmapData.js обязан иметь:

  id        : kebab-case, уникальный, латиница
  title     : <= 30 символов, без точки
  icon      : семантическое kebab-case имя из реестра src/components/Icon.jsx
              (например 'brain', 'tools', 'robot'). Эмодзи запрещены.
  category  : основы | настройка | автоматизация | промпты | агенты
  details:
    what    : что это           (1-2 предложения)
    why     : зачем существует  (1-2 предложения)
    when    : когда применять   (1-2 предложения)
    impact  : что выигрываешь   (1-2 предложения)
    example : конкретный пример (1-3 предложения)
    mistakes: типичная ошибка   (1-2 предложения)
  children  : массив (той же схемы)

Если на любой вопрос нет ответа — узел не готов, идёт в tasks/ideas.md.


================================================================================
6. ОГРАНИЧЕНИЯ ДЕРЕВА
================================================================================

  Глубина          : <= 4 уровня (root -> раздел -> подраздел -> лист)
  Ширина           : <= 12 детей у одного родителя
  Категории        : 5, не больше (фиксированы)
  Размер файла     : <= 150 KB иначе разнести на src/data/sections/*.js
  Узлов всего      : до ~200 без оптимизации layout
  Дубли id         : запрещены, даже после удаления узла


================================================================================
7. ЧТО CLAUDE НЕ ДЕЛАЕТ НИКОГДА
================================================================================

  - не создаёт новый React-проект поверх существующего
  - не переписывает src/ целиком
  - не правит package.json, vite.config.js, index.html без явной задачи
  - не запускает деструктивные команды (rm -rf, git reset --hard) без approval
  - не добавляет runtime-зависимости без обновления docs/architecture.md
  - не вводит TypeScript / Tailwind / styled-components / state managers
  - не плодит подпапки в prompts/, docs/, tasks/
  - не создаёт новые верхнеуровневые папки без апдейта CLAUDE.md
  - не вводит новые категории, если задачу решают 5 существующих
  - не реюзает id даже после удаления узла
  - не смешивает языки в одном поле (контент = русский, id = латиница)
  - не выдумывает факты — пишет "требует проверки" при сомнении
  - не пишет узел без полных 6 полей details
  - не молча удаляет узлы — сначала метка deprecate в backlog
  - не вызывает один skill из другого — только через workflow
  - не предлагает MCP, если задачу решает чистый Claude
  - не предлагает sub-agent для линейной задачи

10. CODE SAFETY
================================================================================

  - перед правкой mindmapData.js — grep по id чтобы избежать дублей
  - после правки — упомянуть npm run build / dev для проверки
  - изменения UI — обязательная проверка accessibility-review
  - destructive операции — только с явным согласием в текущей итерации
  - .claude/settings.local.json содержит deny на package.json /
    vite.config.js / index.html / rm-rf / git reset --hard

12. КОРОТКО: КАК CLAUDE ПРИНИМАЕТ РЕШЕНИЯ
================================================================================

  1. Читает CLAUDE.md и tasks/current.md
  2. Распознаёт тип запроса (контент / архитектура / UI / workflow / факт)
  3. Выбирает один skill по triggers
  4. Следует SKILL.md как чек-листу
  5. Если задача за пределами skills — задаёт уточняющий вопрос,
     не выдумывает
  6. Любую правку фиксирует в tasks/current.md
  7. При сомнении в синтаксисе после правки кода — упоминает
     npm run build
  8. При сомнении в фактах про Claude — отмечает "требует проверки"
  9. При риске сломать архитектуру — отказывается и ссылается
     на это место в инструкции
