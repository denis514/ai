### 🧭 Сессия 2026-08-19 (продолжение 2) — перенос прогресса в аккаунт

Проверяли перед тем, как звать людей входить (шаг 2 плана), и нашли, что
обещание «войдите — прогресс сохранится» держалось только наполовину.

**Как было устроено:** при входе данные из браузера один раз копировались в
облако (это работало). Обратной дороги не было вообще: рабочее состояние всегда
бралось из localStorage, облако читалось только для цифр в панели профиля.
Хуже: точечные синки (`syncNodeProgress`, `syncBookmarks`) считали браузер
источником правды и **удаляли из облака всё, чего нет локально**. Вход на втором
устройстве + одна отметка = данные с первого устройства стёрты.

**Что сделано:**
- `pullRemoteToLocal()` — забирает из Supabase и **сливает** с локальным.
  Правила слияния вынесены в `src/services/progressMerge.js` (без зависимостей,
  чтобы гонять обычным `node`): шаги курсов объединяются, номер шага берётся
  больший, дата завершения не теряется; у тем «на повторение» сильнее
  «просмотрено»; закладки объединяются по паре тип+id с ранней датой.
  Слияние никогда не удаляет.
- Порядок в `AuthContext`: сначала pull, потом push. При свежем входе — оба,
  при восстановлении сессии — только pull.
- Запись в облако закрыта, пока для пользователя не прошёл pull (`hydrated`).
  Это и есть предохранитель от стирания.
- Хуки прогресса/закладок перечитывают localStorage по событию
  `atlas:local-hydrated` (событие `storage` в своей вкладке не срабатывает).
- Текст в панели профиля приведён к правде: «закрепятся за вами и подтянутся
  на других устройствах».
- `npm run test:merge` — 9 проверок правил слияния.

**Проверено:** правила слияния — тестом; перечитывание хуками — вживую
(записал данные в браузер, стрельнул событием, панель профиля обновилась без
перезагрузки: 3 закладки, 2 просмотрено + 1 «вернуться», 1 курс пройден).
⚠️ **Не проверено вживую:** сам вход в аккаунт и обмен с Supabase — для этого
нужен аккаунт владельца. Что проверить: войти на устройстве A, отметить
закладку; войти на устройстве B, убедиться, что закладка видна; поставить там
вторую; вернуться на A и убедиться, что обе на месте.

**Известное ограничение:** слияние происходит при входе и при запуске с активной
сессией. Два устройства, работающие ОДНОВРЕМЕННО, узнают о правках друг друга
только при следующем запуске. Полное решение — метки времени на каждой записи,
отдельная задача.
