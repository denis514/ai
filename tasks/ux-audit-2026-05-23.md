## 4. Top-7 системных проблем

### 🔴 Проблема 1: PromptLibraryModal + PromptModal стек ломает ESC (P0)
- **Files:** `src/components/PromptLibraryModal.jsx:88-98`
- **Сценарий:**
  1. Открой Cmd+K → Библиотека промптов
  2. Кликни на любой промпт → открывается PromptModal поверх
  3. Нажми ESC → закрылся PromptModal, но **ESC дальше не работает**
     для PromptLibraryModal (`!openPrompt` условие)
- **Текущее:** Conditional `if (!openPrompt) handleClose()` блокирует
  ESC даже после того как PromptModal закрылся (нужно ещё раз нажать)
- **Ожидаемое:** ESC всегда закрывает топовое окно. Двойной ESC → закрывает
  два уровня. Сейчас работает, но **не интуитивно** — первый ESC не
  показывает что эффект применился к topmost layer.
- **Фикс:** Раздельные `keydown` handler'ы в каждом модале с
  `event.stopPropagation()`. Или единый `useModalStack` hook.

### 🔴 Проблема 2: TutorialModal `suspended` блокирует все взаимодействия (P0)
- **Files:** `src/components/TutorialModal.jsx:199-201, 298-299`
- **Сценарий:**
  1. Открой TutorialModal
  2. Кликни на gated step (требует auth) → открывается AuthModal,
     TutorialModal становится `suspended`
  3. Закрой AuthModal без логина (ESC)
  4. **Tutorial остался открытым с suspended=true → ESC не работает**
- **Текущее:** `suspended` сохраняется после закрытия AuthModal. Только
  если родитель явно сбросит — взаимодействие восстановится.
- **Ожидаемое:** AuthModal-close должен сбрасывать suspended на parent.
- **Фикс:** В `handleTutorialRequestAuth` (App.jsx) — при закрытии AuthModal
  с любым исходом сбросить `tutorialAwaitingAuth = false`.

### 🟡 Проблема 3: Focus не возвращается на trigger (P1)
- **Files:** все модалы — у НИ ОДНОГО нет focus return на trigger
- **Сценарий:**
  1. Сфокусируйся клавиатурой на «Помощь» (FAB)
  2. Нажми Space → открылся HelpModal
  3. ESC → модал закрылся
  4. **Focus теперь на body, а не на «Помощь»**
  5. Tab уходит в верхний-левый угол приложения, не туда где был
- **Текущее:** Никто не сохраняет `document.activeElement` перед open
- **Ожидаемое:** Pattern из react-aria или ручной useRef + useEffect cleanup
- **Фикс:** Создать `useFocusReturn()` hook. Применить в каждом модале
  с одной строкой. Эффект: keyboard navigation станет profession-grade.

### 🟡 Проблема 4: Inconsistent scroll-lock (P1)
- **Files:** TutorialModal, WorkflowsModal, HelpModal, IntroModal,
  AuthModal, UpdatesArchiveModal — БЕЗ scroll-lock
- **Сценарий:**
  1. Открой TutorialModal на mobile
  2. Прокручивай контент → **под модалом тоже скроллится карта**
  3. Закроешь модал — карта в неожиданной позиции
- **Текущее:** Только PromptLibraryModal, PromptModal, BottomSheet,
  CommandPalette имеют scroll-lock (document.body.style.overflow='hidden')
- **Ожидаемое:** Все full-screen overlays должны лочить body-scroll
- **Фикс:** Создать `useBodyScrollLock()` hook. Применить в 6 местах.

### 🟡 Проблема 5: IntroModal без × и без click-outside (P1)
- **Files:** `src/components/IntroModal.jsx`
- **Сценарий:**
  1. Открыть приложение впервые → IntroModal появляется
  2. Хочешь скипнуть → ищешь ×... **нет ×, нет click-outside**
  3. Единственный путь: дойти до последнего слайда + кнопка «Skip»
- **Текущее:** Только ESC (если знаешь) + кнопка Ohita/Skip на последнем
  слайде
- **Ожидаемое:** Visible × кнопка ВСЕГДА. Или Ohita-кнопка на каждом
  слайде.
- **Фикс:** Добавить `.intro-close` в правом верхнем углу.

### 🟡 Проблема 6: CommandPalette без visible × (P1)
- **Files:** `src/components/CommandPalette.jsx`
- **Сценарий:**
  1. Открой Cmd+K
  2. Пользователь не знает что ESC закрывает (нет hint)
  3. **Нет visible × кнопки**
- **Текущее:** ESC + click-outside. Но visual hint отсутствует.
- **Ожидаемое:** Маленькая × в углу или тeкст «ESC чтобы закрыть»
- **Фикс:** Добавить hint в footer палитры

### 🟡 Проблема 7: PromptModal закрывается напрямую к root (P1)
- **Files:** `src/components/PromptModal.jsx` + `App.jsx` `onClose` handler
- **Сценарий:**
  1. Открой Cmd+K → Библиотека промптов → клик на промпт → PromptModal
  2. Закрой PromptModal (×)
  3. **Library уже закрыта** — Library закрылась сама когда PromptModal
     открылся? Или закрывается вместе?
- **Текущее:** В зависимости от триггера — PromptLibraryModal остаётся
  открытым ИЛИ закрывается. Inconsistent.
- **Ожидаемое:** Если открыл PromptModal из Library — закрытие PromptModal
  возвращает в Library. Если открыл из inline-link в узле — закрытие
  PromptModal возвращает в DetailPanel узла.
- **Фикс:** Передавать `returnTo` контекст. Или использовать тот же
  паттерн `MinimizedPill` для PromptModal.

## 5. Эталонные паттерны (что работает хорошо)

### ✨ MinimizedPill — эталонная back-flow реализация
- При cross-link клике из WorkflowsModal/TutorialModal модал сворачивается в пилюлю
- State (selectedTutorial, tutorialId, progress) сохраняется в App.jsx state
- При клике на пилюлю — модал восстанавливается с тем же state
- × на пилюле — explicit dismiss
- Auto-dismiss при закрытии DetailPanel
- **Это эталон для других «открыл из X, хочу вернуться в X» сценариев**

### ✨ Hash-routing — работает безупречно
- `#/ru/tutorial/instructions` deep-link OK
- Browser back/forward работает
- Refresh сохраняет state
- Locale-prefix корректен

### ✨ MinimizedPill recovery
- Если пользователь по дороге кликнул ещё на cross-link — пилюля
  обновится (один уровень стека), не накапливает stale state

## 6. Рекомендации по следующим шагам

### Срочно (P0, ~2-3 часа работы)
1. **PromptLibraryModal ESC stack** — починить условный ESC чтобы
   первый press всегда работал на topmost layer
2. **TutorialModal suspended reset** — в App.jsx при закрытии
   AuthModal через ESC/× сбрасывать `tutorialAwaitingAuth`

### На неделе (P1, ~4-5 часов)
3. **useFocusReturn() hook** — создать общий hook, применить во
   всех модалах (8 мест). Огромный buff для keyboard-users.
4. **useBodyScrollLock() hook** — то же, для 6 модалов без lock
5. **IntroModal close button** — добавить × в правом верхнем
6. **PromptModal returnTo context** — передавать откуда открыли,
   возвращать туда

### Полировка (P2)
7. **CommandPalette ESC hint** — «нажми ESC чтобы закрыть» в footer
8. **Confirmation dialogs** — для сброса прогресса туториала
   (сейчас просто `confirm()` browser-нативный)
9. **Loading skeletons** — где их нет на async-load
10. **Toast notifications** — для success-actions
11. **Undo для случайных удалений** (закладки, completed-courses
    статус)
12. **Mobile swipe-to-dismiss** — унифицировать для всех BottomSheets
