# Инициатива: Аккаунт как Дашборд ученика

**Статус:** open · **Создано:** 2026-06-10 · **Тип:** полноценный процесс (отдельный трек)
**Владелец процесса:** Atlas UX + продукт.

---

## 1. Цель

Превратить страницу `/account` из «страницы настроек» в **личный кабинет-дашборд
ученика**, где **на главном экране всё доступно сразу** — без поиска по разделам.
Боковая панель остаётся для углублённых разделов, но **первый экран = обзор-дашборд**,
который отвечает на вопрос «что мне делать дальше и как мои успехи» за один взгляд.

**Главный принцип (требование пользователя):** заходя в аккаунт, ученик сразу видит
сводку — продолжить обучение, прогресс, что повторить, что нового, мои агенты — без
переключения вкладок. Разделы боковой панели = «развернуть подробнее».

Не делаем «академию/курсы ради курсов» — опираемся только на **текущие возможности
сервиса** (см. §4). Новые функции выделены отдельно как «будущее» (§6).

## 3. Целевая структура

### 3.1 Главный экран = «Обзор» (дашборд, по умолчанию)
Один экран, всё сразу, сверху вниз по приоритету ценности для ученика:

1. **Приветствие + серия дней** — «С возвращением, {имя}» + streak/всего дней.
2. **Продолжить обучение** — карточки активных курсов с % и кнопкой «продолжить»
   (из `useTutorialProgress`/ProfilePanel «в процессе»).
3. **Мой прогресс одним взглядом** — плитки: изучено узлов / на повторение / закладки /
   пройдено курсов из N (из `useSupabaseStats`).
4. **На повторение** — короткий список узлов, помеченных к возврату (review-очередь).
5. **Что нового с прошлого визита** — из `whatsNew.js` (новое/обновлено).
6. **Мои агенты и автозапуски** — сводка из Builder: число схем, активные автозапуски,
   последние прогоны (из `scheduleService`/`builder_executions`). Вход в Builder.

Каждый блок дашборда = «виджет» с заголовком, кратким содержимым и ссылкой
«подробнее» → соответствующий раздел боковой панели.

### 3.2 Боковая панель (углублённые разделы)
- **Обзор** (новый, дефолтный) — дашборд выше.
- **Продолжить / Курсы** — полный список курсов (активные + завершённые), фильтры.
- **Прогресс по карте** — изучено / на повторение / закладки с переходом на карту.
- **На повторение** — полная review-очередь.
- **Закладки** — сохранённые узлы.
- **Достижения** — сетка ачивок.
- **Мои агенты** — схемы + автозапуски + история (мост в Builder).
- **Профиль** — имя, email, язык, тема, звук.
- **Данные и приватность / Сессия / Удаление** — как сейчас (обслуживание, внизу).

## 4. Опора на текущие возможности сервиса

| Виджет дашборда | Источник (уже существует) |
|-----------------|---------------------------|
| Продолжить обучение | `useTutorialProgress`, ProfilePanel «в процессе» |
| Прогресс (изучено/повтор/закладки) | `useSupabaseStats` (viewedIds/reviewIds/bookmarkNodeIds) |
| На повторение | review-очередь узлов (node_progress) |
| Что нового | `src/data/whatsNew.js` |
| Достижения | ProfilePanel achievements |
| Активность (streak/дни) | `useSupabaseStats` |
| Мои агенты / автозапуски | `scheduleService` (`listAllSchedules`, `listRecentRuns`), `builder_workflows` |

Всё это **уже реализовано** — процесс в основном про сборку дашборда и перенос, а не
про новую бизнес-логику.

## 5. Фазы (полноценный процесс)

- [ ] **Фаза 0 — каркас дашборда.** Раздел «Обзор» как дефолтный; сетка виджетов
  (адаптивная); пустые состояния. Только вёрстка + заглушки данных.
- [ ] **Фаза 1 — ядро ученика (самое ценное).** Виджеты «Продолжить обучение» +
  «Мой прогресс» + «На повторение». Реальные данные из существующих хуков.
- [x] **Фаза 2 — вовлечение.** ✅ Виджеты «Что нового» (TTL 60 дн., клик → узел/курс,
  пометка «прочитано») + «Достижения» (по данным Supabase) на дашборде.
- [ ] **Фаза 3 — мост в Builder.** Виджет «Мои агенты и автозапуски» (сводка + входы).
- [ ] **Фаза 4 — углублённые разделы.** Полные страницы боковой панели (Курсы, Прогресс,
  На повторение, Закладки, Достижения, Мои агенты), куда ведут ссылки «подробнее».
- [ ] **Фаза 5 — гость vs вошедший.** Для гостя — что показываем (локальный прогресс),
  мягкий призыв войти ради синхронизации.
- [ ] **Фаза 6 — барьеры.** quality-gate (код) + mobile-gate (адаптив дашборда) перед push.

Каждая фаза: build ✅ + визуальная проверка ✅ + (для UI) mobile-gate.

## 6. Будущее (новые функции, вне текущего объёма)

Отмечено честно — этого сегодня в сервисе нет, требует отдельной разработки:
- **Цель обучения** + напоминания/уведомления (нет канала напоминаний).
- **Заметки** ученика к узлам.
- **Сертификат/итог** по завершённому learning path.

Эти пункты — кандидаты в `tasks/ideas.md`, не в этот трек.

## 7. Принципы / ограничения

- React 18 функциональные компоненты, чистый CSS, иконки только через `<Icon>`.
- i18n: новые ключи во все три локали (ru/en/fi) — `t()` возвращает ключ при отсутствии.
- Не дублировать логику ProfilePanel — переиспользовать существующие хуки/API.
- Данные пользователя — под RLS Supabase; гость — локально.
- Дашборд обязан быть читаемым на телефоне (виджеты в один столбец).
